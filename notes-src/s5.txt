# p5-1 | 오늘 배울 다섯 가지 | Ch 15
sum: 4회차에서 만든 Student 클래스에 **this, 소멸자, static 멤버, 템플릿, friend** 를 하나씩 붙여 봐요. 이 중 **소멸자와 템플릿**이 가장 중요해요.
ana: 🧰 지난 시간에 지은 집(Student)에 공구 다섯 개로 설비를 하나씩 추가하는 시간이에요.
h: 지난 시간의 Student
code:
#include <string>
#include <string_view>

class Student {
    std::string m_name {};
    int m_score {};
public:
    Student() = default;
    Student(std::string_view n, int s) : m_name { n } { setScore(s); }
    const std::string& getName() const { return m_name; }
    void setScore(int v) { if (v >= 0 && v <= 100) m_score = v; }
};
:end
p: 데이터와 동작을 한 덩어리로 묶었고(클래스), 바깥이 함부로 못 바꾸게 막았고(private), 만들 때 값을 정하게 했어요(생성자). 오늘은 여기에 다섯 가지를 더해요.
h: 다섯 가지 도구
tbl: 도구 | 한 줄 설명 | 비중
r: this 포인터 | 멤버 함수가 “지금 나를 부른 객체”를 알아내는 방법 | 짧게
r: 소멸자 | 객체가 사라질 때 자동으로 불리는 뒷정리 함수 | ⭐ 크게
r: static 멤버 | 객체마다가 아니라 클래스 전체에 **딱 하나** 있는 변수 | 보통
r: 템플릿 | 타입을 빈칸으로 남겨 둔 함수·클래스 | ⭐ 크게
r: friend | 바깥 함수 하나에게만 private을 보여 주기 | 짧게
h: 오늘이 끝나면 할 수 있어야 할 것
li: 뒷정리가 **자동으로** 되는 클래스 만들기 (소멸자)
li: “지금까지 만든 학생 수”, “다음 학번”처럼 **모든 객체가 함께 쓰는 값** 다루기 (static)
li: **타입만 다른** 함수나 클래스를 하나로 합치기 (템플릿)
star: 5회차 핵심은 **소멸자(자동 뒷정리)** 와 **템플릿(타입을 빈칸으로)** 이에요.
trap: 모든 클래스에 습관처럼 소멸자를 씀 > 생성자에서 시작한 일이 있을 때만 (5-4) > string·vector 멤버는 각자 알아서 정리돼요
trap: static을 “상수”라는 뜻으로 오해 > static = 클래스에 하나 (5-5) > 값은 얼마든지 바뀔 수 있어요
mem: **티·소·스·템·프** (this · 소멸자 · static · 템플릿 · friend)
key: 도구 다섯: this · 소멸자 · static · 템플릿 · friend
key: 가장 중요한 건 소멸자와 템플릿
key: 목표: 자동 뒷정리, 함께 쓰는 값, 타입 일반화

# p5-2 | this 포인터: 나를 부른 객체 | Ch 15.1
sum: **this** 는 “이 멤버 함수를 부른 객체”의 주소예요. 멤버 함수 안에서 `name` 이라고 쓰면 컴파일러는 그걸 `this->name` 으로 읽어요.
ana: 🙋 this는 멤버 함수가 “지금 나를 부른 사람이 누구지?” 하고 확인하는 명찰이에요.
h: 멤버 함수는 누구의 값인지 어떻게 알까요?
p: print 함수는 하나뿐이고 인자도 받지 않는데, `a.print()` 를 부르면 a의 이름을, `b.print()` 를 부르면 b의 이름을 출력했어요. 비밀은 **부른 객체의 주소가 몰래 함께 넘어간다**는 거예요. 그 주소가 this예요.
code:
#include <iostream>
#include <string>

class Student {
public:
    std::string name {};
    void whoAmI()
    {
        std::cout << "나를 부른 객체 주소: " << this << ", 이름: " << this->name << '\n';
    }
};

int main()
{
    Student a {}; a.name = "홍길동";
    Student b {}; b.name = "김철수";
    std::cout << "a 의 주소: " << &a << '\n';
    a.whoAmI();     // 이 안에서 this == &a
    std::cout << "b 의 주소: " << &b << '\n';
    b.whoAmI();     // 이 안에서 this == &b
    return 0;
}
:end
out: 실행 결과 (주소 값은 실행할 때마다 달라요)
a 의 주소: 0x7ffd1a20
나를 부른 객체 주소: 0x7ffd1a20, 이름: 홍길동
b 의 주소: 0x7ffd1a40
나를 부른 객체 주소: 0x7ffd1a40, 이름: 김철수
:end
p: a의 주소와 this가 같고, b의 주소와 this가 같아요. this는 포인터라서 멤버에 접근할 때 `->` 를 써요(3-10에서 배운 것처럼).
h: this가 꼭 필요한 순간: 이름이 같을 때
p: 매개변수 이름을 멤버 이름과 똑같이 지으면, 함수 안에서 그 이름은 **매개변수**를 가리켜요. 그래서 `name = name;` 은 매개변수를 자기 자신에게 넣을 뿐, 멤버는 그대로예요.
code:
#include <iostream>
#include <string>
#include <string_view>

class Student {
    std::string name {};
    int score {};
public:
    void setBad(std::string_view name, int score)
    {
        name = name;          // 매개변수 name 에 매개변수 name 을 넣음 → 멤버는 그대로
        score = score;
    }
    void setGood(std::string_view name, int score)
    {
        this->name = name;    // this->name 은 멤버, 오른쪽 name 은 매개변수
        this->score = score;
    }
    void print() const { std::cout << "[" << name << "] " << score << "점\n"; }
};

int main()
{
    Student a {};
    a.setBad("홍길동", 90);
    a.print();
    a.setGood("홍길동", 90);
    a.print();
    return 0;
}
:end
out: 실행 결과
[] 0점
[홍길동] 90점
:end
p: 첫 줄의 빈 대괄호 `[]` 와 0점을 보세요. setBad는 멤버를 전혀 바꾸지 못했어요. setGood은 `this->` 로 멤버를 정확히 가리켜서 제대로 들어갔어요.
warn: `name = name;` 은 문법상 정상이라 **오류가 나지 않아요**. GCC 기본 설정에서는 경고도 없어요. 가장 안전한 습관은 멤버 이름에 `m_` 을 붙여 매개변수와 이름을 다르게 하는 거예요.
star: this = **부른 객체의 주소**. 멤버 이름과 매개변수 이름이 같으면 `this->멤버` 로 구분해요.
trap: 매개변수와 멤버 이름이 같은데 `name = name;` > `this->name = name;` (또는 멤버를 `m_name` 으로) > 오류 없이 아무 일도 일어나지 않아요
trap: `this.name` > `this->name` > this는 포인터라서 `->` 를 써요
mem: this = **명찰** (“나를 부른 게 누구?”)
key: this = 이 함수를 부른 객체의 주소
key: 멤버 이름은 사실 `this->멤버`
key: 이름이 같으면 `this->` 로 구분, 애초에 `m_` 으로 다르게

# p5-3 | 소멸자: 사라질 때 자동으로 불리는 함수 | Ch 15.4
sum: **소멸자** `~클래스이름()` 은 객체가 사라질 때 **자동으로 불려요**. 인자도 반환형도 없고, 클래스마다 **딱 하나**예요.
ana: 🧹 생성자가 입주할 때 하는 일이라면, 소멸자는 이사 나갈 때 하는 청소예요. 퇴실(블록 끝)하면 저절로 해요.
h: 언제 불리나요?
p: 1회차·2회차에서 배웠듯이, 중괄호 블록 안에서 만든 변수는 블록이 끝나면 사라져요. 객체도 똑같이 사라지는데, 사라지기 **직전에** 소멸자가 한 번 불려요.
code:
#include <iostream>
#include <string>
#include <string_view>

class Guard {
    std::string m_name {};
public:
    Guard(std::string_view n) : m_name { n } { std::cout << m_name << " 생성\n"; }
    ~Guard() { std::cout << m_name << " 소멸\n"; }     // 소멸자: 이름 앞에 ~
};

int main()
{
    Guard a { "첫째" };
    {
        Guard b { "둘째" };
    }                             // ← 이 블록이 끝나는 순간 b 가 사라져요
    std::cout << "main 끝\n";
    return 0;
}                                 // ← main 이 끝나는 순간 a 가 사라져요
:end
out: 실행 결과
첫째 생성
둘째 생성
둘째 소멸
main 끝
첫째 소멸
:end
p: 소멸자를 직접 부른 적이 없는데도 “둘째 소멸”과 “첫째 소멸”이 찍혔어요. 컴파일러가 블록이 끝나는 자리에 소멸자 호출을 몰래 넣어 주기 때문이에요.
h: 생성자와 소멸자 비교
tbl:  | 생성자 | 소멸자
r: 언제 불리나요 | 객체가 만들어질 때 | 객체가 사라질 때
r: 이름 | `Guard()` | `~Guard()`
r: 인자 | 받을 수 있어요 | **못 받아요**
r: 반환형 | 없어요 | 없어요
r: 개수 | 여러 개 가능 | **딱 하나**
r: 하는 일 | 준비 | 뒷정리
h: 멤버가 있으면 순서는?
p: 객체 안에 다른 객체(멤버)가 있으면, 만들 때는 **멤버 먼저** 만들고, 없앨 때는 **자기 자신 먼저** 없앤 뒤 멤버를 거꾸로 없애요.
code:
#include <iostream>
#include <string>
#include <string_view>

class Part {
    std::string m_name {};
public:
    Part(std::string_view n) : m_name { n } { std::cout << m_name << " 생성\n"; }
    ~Part() { std::cout << m_name << " 소멸\n"; }
};

class Machine {
    Part m_engine { "엔진" };    // 먼저 선언
    Part m_wheel { "바퀴" };     // 나중에 선언
public:
    Machine()  { std::cout << "기계 생성\n"; }
    ~Machine() { std::cout << "기계 소멸\n"; }
};

int main()
{
    Machine m {};
    return 0;
}
:end
out: 실행 결과
엔진 생성
바퀴 생성
기계 생성
기계 소멸
바퀴 소멸
엔진 소멸
:end
p: Machine의 소멸자에는 엔진과 바퀴를 정리하는 코드가 없는데도 둘 다 소멸됐어요. **멤버의 소멸자는 자동으로 불리기 때문**이에요. 그래서 멤버가 string, vector처럼 스스로 정리하는 타입뿐이라면 소멸자를 따로 쓸 필요가 없어요.
star: 만들 때는 **멤버 → 자신**, 없앨 때는 **자신 → 멤버(역순)**.
trap: 소멸자에 인자를 넣음 `~Guard(int x)` > `~Guard()` > 소멸자는 인자를 받을 수 없어요
trap: 소멸자에 반환형을 붙임 `void ~Guard()` > `~Guard()` > 소멸자는 반환형이 없어요
trap: 소멸자를 `Guard()` 로 씀 (~ 빠짐) > `~Guard()` > ~가 없으면 또 하나의 생성자가 돼요
mem: `~` 는 **물결** — 파도에 쓸려 사라질 때 불려요
key: 소멸자 `~클래스이름()`: 인자·반환형 없음, 하나뿐, 자동 호출
key: 블록이 끝날 때 만든 순서의 반대로 사라져요
key: 멤버의 소멸자는 자동 → 대부분 소멸자를 안 써도 돼요

# p5-4 | Timer 로 배우는 RAII | Ch 15.4
sum: **생성자에서 시작하고 소멸자에서 끝내면**, 중괄호로 감싸기만 해도 뒷정리가 저절로 돼요. 이 방식을 **RAII** 라고 해요.
ana: ⏱️ 방문에 스톱워치를 달아 둔 것과 같아요. 방에 들어가면(생성) 시작되고, 나오면(소멸) 자동으로 멈추고 걸린 시간을 알려 줘요.
h: Timer 클래스
p: 생성자에서 “지금 시각”을 기록하고, 소멸자에서 “지금 시각 − 시작 시각”을 출력하는 클래스예요. 시간을 재고 싶은 코드를 중괄호로 감싸고 그 안에 Timer를 하나 만들기만 하면 돼요.
code:
#include <chrono>
#include <iostream>
#include <string>
#include <string_view>
#include <thread>

class Timer {
    std::string m_label {};
    std::chrono::steady_clock::time_point m_start {};           // 시작 시각을 담는 변수
public:
    Timer(std::string_view label)
        : m_label { label }, m_start { std::chrono::steady_clock::now() }   // 지금 시각 기록
    { }
    ~Timer()
    {
        auto elapsed = std::chrono::steady_clock::now() - m_start;          // 걸린 시간
        auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(elapsed).count();
        std::cout << "[" << m_label << "] " << ms << " ms\n";
    }
};

int main()
{
    {
        Timer t { "1단계" };
        std::this_thread::sleep_for(std::chrono::milliseconds(120));   // 120ms 동안 일하는 척
    }   // ← 여기서 t 가 사라지며 소멸자가 시간을 출력해요
    {
        Timer t { "2단계" };
        std::this_thread::sleep_for(std::chrono::milliseconds(80));
    }
    return 0;
}
:end
out: 실행 결과 (대략)
[1단계] 120 ms
[2단계] 80 ms
:end
tbl: 처음 보는 이름 | 뜻 (외울 필요는 없어요)
r: `std::chrono::steady_clock::now()` | 지금 시각
r: `time_point` | 시각 하나를 담는 타입
r: `duration_cast<milliseconds>(...).count()` | 시간 차이를 밀리초 숫자로 바꾸기
r: `std::this_thread::sleep_for(...)` | 그 시간 동안 잠깐 멈추기 (일하는 척)
ref: std::chrono 문법은 시험용으로 외울 필요 없어요. “생성자에서 시작 시각 기록, 소멸자에서 경과 시간 출력”이라는 **구조**만 이해하면 돼요.
h: RAII 가 뭔가요?
flow: 객체를 만든다 > 생성자에서 무언가를 **시작** (시간 재기, 파일 열기, 메모리 잡기) || 쓴다 > 중간에 return이 몇 번 있든, 어디로 빠져나가든 || 객체가 사라진다 > 소멸자에서 **뒷정리**가 자동으로
term: RAII | Resource Acquisition Is Initialization | 뒷정리를 객체의 수명에 맡기는 방식. “끝내는 걸 깜빡하는” 실수가 사라져요
p: 지금까지 std::string이나 std::vector를 쓰면서 메모리를 직접 돌려준 적이 없죠? 그 클래스들이 소멸자에서 알아서 메모리를 돌려주기 때문이에요. 이게 바로 RAII예요.
ref: 9회차(메모리 직접 다루기)와 11회차(파일 열고 닫기)에서 RAII가 진짜로 빛나요.
h: 소멸자를 직접 써야 할 때와 아닐 때
tbl: 상황 | 소멸자를 쓸까요?
r: 멤버가 int, double, string, vector 뿐 | ❌ 안 써요 — 각자 알아서 정리돼요
r: 생성자에서 무언가를 **시작**했고 끝내야 함 (Timer) | ✅ 끝내는 코드를 소멸자에
r: 파일을 열거나 메모리를 직접 잡음 (9·11회차) | ✅ 닫고 돌려주는 코드를 소멸자에
warn: 소멸자를 `a.~Timer();` 처럼 **직접 부르면 안 돼요**. 블록이 끝날 때 자동으로 한 번 더 불려서 같은 객체가 **두 번** 정리돼요.
star: 소멸자를 쓸지 판단하는 질문은 하나예요. “**생성자에서 시작한 게 있나요?**” 있으면 소멸자에서 끝내고, 없으면 안 써요.
trap: `a.~Timer();` 로 소멸자를 직접 부름 > 블록이 끝나면 자동으로 불리게 둠 > 나중에 또 불려서 두 번 정리돼요
trap: 멤버가 string뿐인데 소멸자를 만들어 무언가를 지우려 함 > 소멸자를 쓰지 않음 > string은 스스로 정리돼요
mem: RAII = **문에 단 스톱워치** (들어가면 시작, 나오면 자동 정지)
key: RAII = 생성자에서 시작, 소멸자에서 끝
key: 어떻게 빠져나가든 소멸자는 불려요
key: 소멸자는 직접 부르지 않아요

# p5-5 | static 멤버: 클래스에 하나뿐인 변수 | Ch 15.6~15.7
sum: 멤버 변수에 **static** 을 붙이면 객체마다 따로 생기지 않고 **클래스 전체에 딱 하나**만 생겨요. **static 멤버 함수**는 객체 없이 `클래스이름::함수()` 로 부르고, 안에 **this가 없어요**.
ana: 🏫 일반 멤버는 학생마다 하나씩 있는 공책이고, static 멤버는 교실 앞에 하나뿐인 칠판이에요. 누가 칠판에 쓰면 모두가 같은 내용을 봐요.
h: 왜 필요할까요?
p: “지금까지 만든 학생 수”를 세고 싶다고 해 볼게요.
tbl: 방법 | 문제
r: 일반 멤버 변수 `int m_count` | 학생마다 따로 생겨서 전체 수를 못 세요
r: 전역 변수 `int g_count` | 셀 수는 있지만, 아무 코드나 바꿀 수 있고 이름이 바깥에 노출돼요
r: **static 멤버 변수** | ✅ 클래스 안에 있으면서(private 가능) 전체에 하나
h: static 멤버 변수와 함수
code:
#include <iostream>
#include <string>
#include <string_view>

class Student {
    inline static int s_count { 0 };     // 클래스 전체에 하나 (모든 Student 가 같이 씀)
    std::string m_name {};               // 학생마다 하나
public:
    Student(std::string_view n) : m_name { n } { ++s_count; }   // 생기면 +1
    ~Student() { --s_count; }                                   // 사라지면 -1
    static int count() { return s_count; }                      // static 멤버 함수
};

int main()
{
    std::cout << Student::count() << '\n';   // 객체가 하나도 없어도 부를 수 있어요 → 0
    Student a { "홍길동" };
    Student b { "김철수" };
    std::cout << Student::count() << '\n';   // 2
    return 0;
}
:end
out: 실행 결과
0
2
:end
tbl: 코드 조각 | 뜻
r: `static int s_count` | 클래스 전체에 하나뿐인 변수
r: `inline` | 헤더에 써도 정의가 하나로 합쳐지게 해요 (C++17, 2회차 inline constexpr과 같은 이유)
r: `s_` | static 멤버라는 표시로 붙이는 관습 (`m_` 처럼)
r: `static int count()` | 객체 없이 부를 수 있는 멤버 함수
r: `Student::count()` | 객체 이름이 아니라 **클래스 이름**으로 불러요
h: static 멤버 함수에는 this가 없어요
p: static 멤버 함수는 객체 없이 불리기 때문에 “나를 부른 객체”가 없어요. 그래서 `m_name` 같은 **객체마다 있는 멤버**를 쓸 수 없어요. (어느 학생의 이름인지 모르니까요.) static 멤버 변수나 매개변수로 받은 객체는 쓸 수 있어요. 지킬 객체가 없으니 `const` 도 붙일 수 없어요.
h: 수명 비교
tbl:  | 지역 변수 | static 멤버 | 전역 변수
r: 언제까지 살아 있나요 | 블록이 끝날 때까지 | 프로그램 끝까지 | 프로그램 끝까지
r: 누가 쓸 수 있나요 | 그 블록 안 | 클래스가 정해요 (private 가능) | 아무나
star: static 멤버 함수에는 **this가 없어서** 객체별 멤버(`m_name`)를 쓸 수 없고 const도 못 붙여요.
trap: static 멤버 함수 안에서 `m_name` 사용 > static 멤버나 매개변수로 받은 객체만 사용 > 어느 객체의 m_name인지 몰라 컴파일 오류예요
trap: `a.count()` 처럼 객체로만 부를 수 있다고 생각 > `Student::count()` > 객체가 없어도 클래스 이름으로 부를 수 있어요
mem: static = **칠판**(반에 하나), 일반 멤버 = **공책**(학생마다)
key: static 멤버 변수 = 클래스에 하나, `inline static` 으로 헤더에
key: static 멤버 함수 = `클래스::함수()`, this 없음
key: 프로그램이 끝날 때까지 살아 있어요

# p5-6 | 실전: 학번 자동 부여와 인원 세기 | Ch 15.6~15.7
sum: static 변수 두 개로 **겹치지 않는 학번**(`s_nextId++`)과 **지금 인원 수**(생성자 `++`, 소멸자 `--`)를 자동으로 관리해요.
ana: 🎫 은행 번호표 기계와 같아요. 한 번 뽑힌 번호는 손님이 떠나도 다시 나오지 않아요. 대기 인원은 손님이 떠나면 줄어들어요.
h: 코드
code:
#include <iostream>
#include <string>
#include <string_view>

class Student {
    inline static int s_count { 0 };          // 지금 살아 있는 학생 수
    inline static int s_nextId { 20250001 };  // 다음에 줄 학번
    std::string m_name {};
    int m_id {};
public:
    Student(std::string_view n) : m_name { n }, m_id { s_nextId++ } { ++s_count; }
    ~Student() { --s_count; }
    int id() const { return m_id; }
    static int count() { return s_count; }
};

int main()
{
    Student a { "홍길동" };
    Student b { "김철수" };
    std::cout << "a 학번 " << a.id() << ", 인원 " << Student::count() << '\n';
    {
        Student c { "이영희" };
        std::cout << "c 학번 " << c.id() << ", 인원 " << Student::count() << '\n';
    }   // ← c 가 사라지며 소멸자가 --s_count
    std::cout << "블록 밖 인원 " << Student::count() << '\n';
    return 0;
}
:end
out: 실행 결과
a 학번 20250001, 인원 2
c 학번 20250003, 인원 3
블록 밖 인원 2
:end
h: 한 줄씩 따라가기
tbl: 순간 | s_nextId | s_count | 무슨 일
r: a 생성 | 20250001 → 20250002 | 1 | a는 20250001을 받아요 (후위 ++: 지금 값을 주고 올림)
r: b 생성 | 20250002 → 20250003 | 2 | b는 20250002
r: c 생성 | 20250003 → 20250004 | 3 | c는 20250003
r: c 소멸 (블록 끝) | 20250004 그대로 | 2 | 인원만 줄고, 학번은 되돌아가지 않아요
p: `m_id { s_nextId++ }` 의 `++` 가 뒤에 붙어 있다는 게 중요해요. 2회차에서 배운 대로 **후위 ++는 지금 값을 먼저 주고 나서** 올려요. 전위(`++s_nextId`)로 쓰면 첫 학번이 20250002가 돼요.
star: c의 학번이 **20250003** 인 이유는 b가 20250002를 가져갔기 때문이에요. 출력 예측 문제로 나오기 좋아요.
trap: `m_id { ++s_nextId }` (전위) > `m_id { s_nextId++ }` (후위) > 첫 학번이 20250002부터 시작해요
trap: 소멸자에서 `--s_nextId` 까지 함 > 소멸자에서는 `--s_count` 만 > 이미 나간 번호가 다시 나와서 학번이 겹쳐요
mem: 학번 = **번호표**(다시 안 나옴), 인원 = **대기 인원**(나가면 줄어듦)
key: 학번: `m_id { s_nextId++ }` (지금 값을 주고 올림)
key: 인원: 생성자 `++s_count`, 소멸자 `--s_count`
key: 블록이 끝나면 소멸자 → 인원 감소

# p5-7 | 함수 템플릿: 타입을 빈칸으로 | Ch 11.6~11.7
sum: **`template <typename T>`** 를 붙이면 타입을 빈칸 T로 둔 함수를 만들 수 있어요. 부를 때 넣은 인자를 보고 컴파일러가 T를 정해서 **그 타입용 함수를 찍어내요**.
ana: 🍪 쿠키 틀이에요. 틀은 하나인데 초코 반죽을 넣으면 초코 쿠키, 녹차 반죽을 넣으면 녹차 쿠키가 나와요. T는 반죽 자리예요.
h: 문제: 타입만 다른 함수를 여러 번 복사
code:
int larger(int a, int b)                         { return a > b ? a : b; }
double larger(double a, double b)                { return a > b ? a : b; }
std::string larger(std::string a, std::string b) { return a > b ? a : b; }
// 몸통이 글자 하나 안 다르고 타입만 달라요
:end
p: 3회차의 오버로딩으로 만들 수는 있지만, 타입이 늘어날 때마다 또 복사해야 하고, 고칠 때는 세 군데를 똑같이 고쳐야 해요.
fix: PPT에 “**4회차**의 오버로드로 세 개를 만들었음”이라고 되어 있지만, 함수 오버로딩은 **3회차**에서 배웠어요.
h: 템플릿으로 하나로 합치기
code:
#include <iostream>
#include <string>

template <typename T>          // "T 는 타입 이름이에요. 무엇인지는 부를 때 정해져요"
T larger(T a, T b)             // 타입이 들어갈 자리에 T
{
    return a > b ? a : b;
}

int main()
{
    std::cout << larger(3, 7) << '\n';          // T = int
    std::cout << larger(2.5, 1.5) << '\n';      // T = double
    std::cout << larger(std::string { "홍길동" }, std::string { "김철수" }) << '\n';   // T = std::string
    return 0;
}
:end
out: 실행 결과
7
2.5
홍길동
:end
tbl: 코드 조각 | 뜻
r: `template <typename T>` | 바로 아래 함수에서 T는 “아직 정하지 않은 타입”이라는 선언
r: `T larger(T a, T b)` | int, double 같은 타입 이름이 들어갈 자리에 T를 써요
r: `larger(3, 7)` | 인자가 int니까 컴파일러가 T = int로 정해요. `<int>` 를 안 써도 돼요
p: 템플릿 자체는 함수가 아니라 **함수를 찍어내는 틀**이에요. `larger(3, 7)` 을 보면 컴파일러가 int용 larger를 만들고, `larger(2.5, 1.5)` 를 보면 double용을 또 만들어요. 결과는 손으로 세 개 만든 것과 같아요.
h: T 가 하나로 정해지지 않으면
code:
larger(3, 7.5);     // ❌ 3 은 int, 7.5 는 double → T 를 하나로 못 정해요
larger(3.0, 7.5);   // ✅ 둘 다 double
:end
out: GCC 실제 출력
error: no matching function for call to 'larger(int, double)'
note:   deduced conflicting types for parameter 'T' ('int' and 'double')
:end
tip: 템플릿 오류는 길게 나오는데, `deduced conflicting types` (T 후보가 서로 다름) 같은 핵심 한 줄만 찾으면 돼요.
star: 템플릿은 **함수를 찍어내는 틀**이에요. `larger(3, 7.5)` 처럼 인자 타입이 다르면 **T 충돌 오류**가 나요.
trap: `larger(3, 7.5)` > `larger(3.0, 7.5)` > T를 int와 double 중 하나로 정할 수 없어요
trap: `template <typename T>` 없이 `T larger(T a, T b)` > 함수 바로 위에 템플릿 선언 > T가 무엇인지 몰라 컴파일 오류예요
mem: 템플릿 = **쿠키 틀**, T = **반죽 자리**
key: `template <typename T>` + 타입 자리에 T
key: 부를 때 인자를 보고 T가 정해져요

# p5-8 | 클래스 템플릿 | Ch 15.5
sum: 클래스도 `template <typename T>` 로 타입을 빈칸으로 만들 수 있어요. 함수와 달리 보통 **`Pair<int>`** 처럼 타입을 직접 적어요. 템플릿은 **정의까지 헤더에** 둬야 해요.
ana: 📦 크기와 모양은 같고 내용물만 다른 택배 상자예요. `상자<사과>`, `상자<책>` — 상자 설계도는 하나예요.
h: 클래스 템플릿 만들기
p: 값 두 개를 담고 더 큰 쪽을 알려 주는 Pair 클래스를, int용과 string용으로 따로 만들지 않고 하나로 만들어 볼게요.
code:
#include <iostream>
#include <string>

template <typename T>
class Pair {
    T m_first {};
    T m_second {};
public:
    Pair(const T& a, const T& b) : m_first { a }, m_second { b } { }
    const T& larger() const { return m_first > m_second ? m_first : m_second; }
};

int main()
{
    Pair<int> nums { 3, 7 };                            // T = int
    Pair<std::string> names { "홍길동", "김철수" };       // T = std::string
    std::cout << nums.larger() << '\n';
    std::cout << names.larger() << '\n';
    return 0;
}
:end
out: 실행 결과
7
홍길동
:end
tbl:  | 함수 템플릿 | 클래스 템플릿
r: T 정하기 | 인자를 보고 **자동** `larger(3, 7)` | 보통 `< >` 안에 **직접** `Pair<int>`
r: 표준 라이브러리 예 | `std::max` | `std::vector<int>`, `std::string`
p: 6회차의 `std::vector<int>` 에서 `<int>` 가 바로 이거예요. vector는 클래스 템플릿이고, `<int>` 를 쓰면 int를 담는 vector 클래스가 찍혀 나와요.
li: `Pair<int>` 와 `Pair<std::string>` 은 **완전히 다른 타입**이에요. 서로 대입할 수 없어요
li: C++17부터는 `Pair p { 3, 7 };` 처럼 `<int>` 를 생략해도 되는 경우가 있어요
h: 함정: 템플릿을 .h 와 .cpp 로 나누면 링크 오류
p: 4회차에서는 “선언은 .h, 몸통은 .cpp”라고 배웠어요. 그런데 템플릿은 예외예요. 컴파일러가 `Pair<int>` 를 찍어내려면 **몸통을 직접 봐야** 하는데, main.cpp를 번역할 때 pair.cpp는 보이지 않거든요(1-1, 컴파일러는 파일을 하나씩 봐요).

# p5-9 | friend: 바깥 함수 하나에게만 열어 주기 | Ch 15.8
sum: **friend** 를 쓰면 클래스가 **고른 바깥 함수 하나**에게만 private 멤버를 보여 줄 수 있어요. 기본은 getter를 쓰고, friend는 정말 필요할 때만 써요.
ana: 🔑 집주인이 친한 친구 한 명에게만 열쇠를 주는 거예요. 친구가 스스로 열쇠를 만들 수는 없어요.
h: 왜 필요할까요?
p: 두 학생의 점수를 비교하는 함수를 생각해 볼게요. “a가 b보다 높은가”는 a와 b를 **똑같이** 다루니까 멤버 함수(`a.isHigher(b)`)보다 바깥 함수 `isHigher(a, b)` 가 자연스러워요. 그런데 바깥 함수는 private 멤버를 못 봐요.
code:
class Student {
    int m_score {};     // private
public:
    Student(int s) : m_score { s } { }
};

bool isHigher(const Student& a, const Student& b)
{
    return a.m_score > b.m_score;   // ❌ 바깥 함수라서 private 에 접근 못 해요
}
:end
out: GCC 실제 출력
error: 'int Student::m_score' is private within this context
:end
h: 해결 방법 두 가지
p: **① getter로 읽기** (기본) — 점수를 읽는 getter가 있으면 그걸 써요.
code:
#include <iostream>

class Student {
    int m_score {};
public:
    Student(int s) : m_score { s } { }
    int getScore() const { return m_score; }
};

bool isHigher(const Student& a, const Student& b)
{
    return a.getScore() > b.getScore();
}

int main()
{
    Student a { 90 }, b { 75 };
    std::cout << std::boolalpha << isHigher(a, b) << '\n';
    return 0;
}
:end

p: 스택은 접시를 쌓는 것처럼 **마지막에 넣은 것을 먼저 꺼내는** 자료 구조예요. push는 맨 위에 올리기, pop은 맨 위를 빼기, top은 맨 위를 보기예요.
code:
#include <iostream>
#include <string>

template <typename T>
class Stack {
    T m_data[10] {};          // 최대 10개를 담는 배열
    int m_size { 0 };         // 지금 몇 개 들어 있는지
public:
    bool push(const T& v)     // 맨 위에 올리기, 꽉 찼으면 false
    {
        if (m_size == 10) return false;
        m_data[m_size++] = v;
        return true;
    }
    void pop() { if (m_size > 0) --m_size; }        // 맨 위 빼기, 비었으면 아무것도 안 함
    const T& top() const { return m_data[m_size - 1]; }   // 맨 위 보기 (비었는지 먼저 확인!)
    int size() const { return m_size; }
    bool empty() const { return m_size == 0; }
};

int main()
{
    Stack<int> s {};
    s.push(1); s.push(2); s.push(3);
    std::cout << s.top() << ' ' << s.size() << '\n';   // 3 3
    s.pop();
    std::cout << s.top() << '\n';                      // 2

    Stack<std::string> names {};
    names.push("홍길동");
    std::cout << names.top() << '\n';                  // 홍길동
    return 0;
}
:end
