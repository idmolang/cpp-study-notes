# p3-1 | 자동 형변환과 부호 섞기 | Ch 10.1~10.3, 10.5
sum: 타입이 다른 값끼리 계산하면 C++가 **알아서 타입을 맞춰요**. 대부분 편리하지만, 부호 있는 수와 없는 수를 섞으면 **−1이 42억으로 바뀌는** 사고가 나요.
ana: 💱 환전과 같아요. 작은 지갑의 돈을 큰 지갑으로 옮기는 건 안전하지만(승격), 큰돈을 작은 지갑에 넣으면 넘치는 만큼 버려져요(축소).
h: 자동 변환 세 종류
tbl: 종류 | 예 | 값을 잃나요
r: 승격 (promotion) | char·short·bool → int, float → double | 안 잃어요 ✅
r: 수치 변환 | double → int, int → short | 잃을 수 있어요 ⚠️
r: 산술 변환 | `a + b` 에서 a와 b의 타입을 하나로 맞춤 | 부호를 섞으면 사고 ⚠️
code:
#include <iostream>

int main()
{
    int i { 0 };
    i = 3.7;                    // 수치 변환: double → int, 0.7 이 버려져요
    std::cout << i << '\n';     // 3

    short a { 1 }, b { 2 };
    auto s { a + b };           // short + short → 계산할 때 int로 승격돼요
    std::cout << sizeof(s) << '\n';   // 4 (int 크기)
    return 0;
}
:end
out: 실행 결과 (일반적인 환경)
3
4
:end
p: 두 번째 결과를 보세요. short끼리 더했는데 결과가 int예요. C++는 int보다 작은 정수(char, short)를 계산할 때 먼저 int로 바꾼 다음 계산해요. `auto` 는 “오른쪽 값을 보고 타입을 알아서 정해 줘”라는 뜻이에요.
fix: PPT 코드가 `short a { 1 }, b { 2 };` 에서 끝나 있어서, “short끼리 더하면 int가 된다”는 마지막 줄을 보충했어요.
h: 부호를 섞으면 생기는 사고
p: int(부호 있음)와 unsigned int(부호 없음)를 한 식에서 비교하면, C++는 int 쪽을 unsigned로 바꿔서 비교해요. 그러면 −1이 4294967295라는 거대한 수가 돼요.
code:
#include <iostream>

int main()
{
    int x { -1 };
    unsigned int y { 1 };
    std::cout << std::boolalpha << (x < y) << '\n';   // -1 < 1 이니까 true...?
    return 0;
}
:end
out: 실행 결과
false
:end
p: −1이 unsigned로 바뀌면서 4294967295가 됐고, 그래서 “4294967295 < 1”을 비교한 셈이 되어 false가 나와요. 6회차에서 배우는 `v.size()` 도 부호 없는 수라서, `int i` 와 비교할 때 같은 문제가 생겨요.
tip: 컴파일 옵션 `-Wconversion -Wsign-conversion` 을 켜면 이런 변환을 경고로 알려 줘요.
star: 부호 있는 수와 없는 수를 섞으면 **부호 있는 쪽이 unsigned로 바뀌어요**. 그래서 `-1 < 1u` 는 **false**.
trap: `int` 와 `unsigned int` 를 그대로 비교 > 한 식에서 부호를 섞지 않기 > −1이 42억이 돼서 비교가 뒤집혀요
mem: unsigned와 만나면 int가 **져서** unsigned 옷으로 갈아입어요
key: 승격(안전) · 수치 변환(잃을 수 있음) · 산술 변환(타입 맞추기)
key: 작은 정수끼리 계산하면 int가 돼요
key: `-1 < 1u` 는 false — 부호를 섞지 않기

# p3-2 | static_cast 와 타입 별칭 | Ch 10.4, 10.6~10.7
sum: 타입을 직접 바꿀 때는 **`static_cast<타입>(값)`** 을 써요. `using 새이름 = 타입;` 은 타입에 **별명**을 붙여 줄 뿐, 새 타입을 만들지는 않아요.
ana: 🏷️ 별칭은 닉네임이에요. “철수”를 “쭈니”라고 불러도 같은 사람이에요. 다른 사람으로 대해 주지는 않아요.
h: 직접 타입 바꾸기
p: 자동 변환에 맡기지 않고 “여기서 이 타입으로 바꾼다”고 분명히 쓰고 싶을 때가 있어요. 대표적인 예가 정수 나눗셈을 실수 나눗셈으로 바꿀 때예요.
code:
#include <iostream>

int main()
{
    int a { 10 }, b { 3 };
    std::cout << a / b << '\n';                         // 3 (정수 나눗셈)
    std::cout << static_cast<double>(a) / b << '\n';    // 3.33333 (a를 double로 바꾼 뒤 나눔)
    return 0;
}
:end
out: 실행 결과
3
3.33333
:end
vs: ❌ C 스타일 | ✅ static_cast
double r = (double)a / b;
// · 어떤 변환인지 안 보여요
// · 위험한 변환도 조용히 해요
// · 코드에서 찾기 어려워요
--
double r = static_cast<double>(a) / b;
// · 값 변환만 허용해요
// · 위험한 변환은 컴파일 오류
// · 눈에 띄고 검색하기 쉬워요
:end
tip: 일부러 소수점을 버릴 때도 `int n { static_cast<int>(4.9) };` 처럼 쓰면 “알고 자른 것”이 드러나요. (`int n { 4.9 };` 는 컴파일 오류)
h: 타입 별칭: 긴 타입에 짧은 이름 붙이기
code:
#include <iostream>
#include <vector>

using Scores = std::vector<int>;    // std::vector<int> 를 Scores 라고 부르기로 해요
using Meter  = double;
using Second = double;

int main()
{
    Scores s { 90, 75 };            // std::vector<int> s { 90, 75 }; 와 똑같아요
    Meter dist { 10 };
    Second time { 2 };
    double v { dist + time };       // ⚠️ 거리 + 시간인데도 오류가 안 나요
    std::cout << v << '\n';
    return 0;
}
:end
out: 실행 결과
12
:end
p: 마지막 계산을 보세요. 거리와 시간을 더하는 건 말이 안 되지만 오류가 나지 않아요. Meter와 Second는 둘 다 그냥 double의 별명이라서, 컴파일러 눈에는 double + double이에요.
tbl: 옛날 방식 | 요즘 방식
r: `typedef std::vector<int> Scores;` | `using Scores = std::vector<int>;` ✅
h: 형변환 한눈에
tbl: 변환 | 값을 잃나요 | 대응
r: 승격 | 안 잃어요 | 신경 안 써도 돼요
r: 수치 변환 | 잃을 수 있어요 | `-Wconversion` 경고 켜기
r: 축소 변환 | 잃어요 | `{ }` 초기화가 막아 줘요
r: 산술 변환 | 부호를 섞으면 | 부호를 섞지 않기
r: 직접 변환 | 의도한 대로 | `static_cast` 로 쓰기
fix: 3회차 표지에 “타입 추론(auto)”과 “함수 템플릿”이 있지만 본문 슬라이드엔 없어요. auto는 “오른쪽 값을 보고 타입을 정해 줌”(`auto x { 5 };` → int)만 알면 되고, 함수 템플릿은 5회차에서 배워요.
star: 형변환 세 원칙 — ① `{ }` 가 축소를 잡는다 ② 부호를 섞지 않는다 ③ 직접 바꿀 땐 `static_cast`.
trap: `(double)a / b` > `static_cast<double>(a) / b` > 어떤 변환인지 드러나지 않아요
trap: `using Meter = double;` 로 단위를 구분하려 함 > 별칭은 구분해 주지 않는다는 걸 알기 > Meter와 Second는 둘 다 그냥 double이에요
mem: 별칭 = **닉네임** (같은 사람)
key: 직접 변환은 `static_cast<타입>(값)`
key: `using 이름 = 타입;` 은 별명, 새 타입이 아니에요
key: 축소는 `{}` 가 막고, 부호는 섞지 않기

# p3-3 | 함수 오버로딩 | Ch 11.1~11.4
sum: **이름은 같고 매개변수의 개수나 타입이 다른** 함수를 여러 개 만들 수 있어요. 부를 때 넣은 인자를 보고 컴파일러가 맞는 걸 골라요. 반환 타입만 다른 건 안 돼요.
ana: 👨‍🍳 “요리해 주세요”라는 주문 하나에, 셰프가 재료(인자)를 보고 레시피를 골라요. 재료가 똑같으면 어떤 레시피인지 고를 수 없어요.
h: 같은 이름, 다른 재료
code:
#include <iostream>

int add(int a, int b)           { return a + b; }
double add(double a, double b)  { return a + b; }       // 타입이 달라요
int add(int a, int b, int c)    { return a + b + c; }   // 개수가 달라요

int main()
{
    std::cout << add(1, 2) << '\n';        // int 두 개 → 첫 번째 add
    std::cout << add(1.5, 2.5) << '\n';    // double 두 개 → 두 번째 add
    std::cout << add(1, 2, 3) << '\n';     // int 세 개 → 세 번째 add
    return 0;
}
:end
out: 실행 결과
3
4
6
:end
tbl: 구분할 수 있어요 ✅ | 구분할 수 없어요 ❌
r: 매개변수의 **개수** | 반환 타입만 다른 경우
r: 매개변수의 **타입** | 매개변수 **이름**만 다른 경우
p: 반환 타입으로 구분할 수 없는 이유는, `add(1, 2);` 처럼 반환값을 쓰지 않고 부를 수도 있기 때문이에요. 그러면 컴파일러가 어느 쪽인지 알 방법이 없어요.
h: 딱 맞는 게 없을 때 고르는 순서
p: 인자 타입과 똑같은 함수가 없으면, 컴파일러는 아래 순서로 “가장 가까운” 함수를 찾아요.
flow: ① 정확히 일치 > 타입이 그대로 맞아요 || ② 승격 > char → int 처럼 안전한 변환으로 맞아요 || ③ 표준 변환 > int → double 처럼 일반 변환으로 맞아요 || ④ 사용자 정의 변환 > 클래스가 정한 변환 (4회차) || ⑤ 가변 인자 > `...` 로 받는 함수
code:
#include <iostream>

void print(int x)    { std::cout << "int: " << x << '\n'; }
void print(double x) { std::cout << "double: " << x << '\n'; }

int main()
{
    print('a');   // char 에 딱 맞는 게 없어요 → char→int 승격이 char→double 보다 먼저 → int 버전
    return 0;
}
:end
out: 실행 결과
int: 97
:end
warn: 같은 단계에 후보가 두 개 이상이면 **모호함(ambiguous)** 컴파일 오류가 나요. 예를 들어 `f(int)` 와 `f(long)` 만 있을 때 `f(3.0)` 을 부르면, double→int와 double→long이 같은 단계(표준 변환)라서 고를 수 없어요.
star: 오버로딩은 **매개변수의 개수와 타입**으로만 구분해요. 고르는 순서는 **정·승·표·사·가**.
trap: 반환 타입만 바꿔서 같은 이름 함수를 하나 더 만듦 > 매개변수를 다르게 > 반환 타입으로는 구분할 수 없어서 컴파일 오류예요
trap: `f(int)`, `f(long)` 만 있는데 `f(3.0)` 호출 > `f(3)` 처럼 인자 타입을 맞추기 > 같은 단계 후보가 둘이라 모호함 오류
mem: **정·승·표·사·가** (정확 → 승격 → 표준 → 사용자 → 가변)
key: 같은 이름 + 다른 매개변수(개수·타입)
key: 반환 타입만 다르면 안 돼요
key: 같은 단계 후보가 둘이면 모호함 오류

# p3-4 | 기본 인자 | Ch 11.5
sum: 매개변수에 **기본값**을 정해 두면, 부를 때 그 인자를 생략할 수 있어요. 기본값은 **오른쪽 매개변수부터** 채우고, **선언(헤더)에 한 번만** 적어요.
ana: 🍔 세트 메뉴의 음료처럼 “말 안 하면 콜라”예요. 음료는 마지막 칸이라 생략할 수 있지만, 버거(앞 칸)를 건너뛰고 음료만 고를 수는 없어요.
h: 쓰는 법
code:
#include <iostream>

void printNumber(int value, int base = 10)   // base 를 안 넘기면 10
{
    if (base == 16)
        std::cout << std::hex << value << std::dec << '\n';   // 16진수로 출력
    else
        std::cout << value << '\n';
}

int main()
{
    printNumber(255);       // base 생략 → 10 → "255"
    printNumber(255, 16);   // base = 16 → "ff"
    return 0;
}
:end
out: 실행 결과
255
ff
:end
h: 규칙 두 가지
tbl: 규칙 | 이유
r: 기본값은 **오른쪽 끝부터** 몰아서 | 인자는 왼쪽부터 순서대로 채워지기 때문에, 앞 칸만 비울 수는 없어요
r: 선언과 정의 중 **한 곳에만** (보통 헤더의 선언) | 두 곳에 모두 쓰면 컴파일 오류예요
code:
// ✅ 오른쪽부터
void f(int a, int b = 0);
// ❌ 기본값 뒤에 기본값 없는 매개변수가 오면 안 돼요
// void g(int a = 1, int b);
:end
warn: 오버로딩과 섞으면 모호해질 수 있어요. `void f(int);` 와 `void f(int, int = 0);` 이 같이 있으면 `f(1)` 은 둘 다 딱 맞아서 컴파일 오류가 나요.
star: 기본 인자는 **오른쪽부터**, **선언에 한 번만**.
trap: `void g(int a = 1, int b);` > `void g(int b, int a = 1);` > 기본값은 오른쪽부터 채워야 해요
trap: 헤더 선언과 .cpp 정의 둘 다에 `= 10` 을 씀 > 헤더 선언에만 > 두 번 적으면 컴파일 오류예요
mem: 기본값은 **꼬리**(오른쪽 끝)부터
key: 기본값이 있으면 그 인자를 생략할 수 있어요
key: 오른쪽부터, 선언에 한 번만
key: 오버로딩과 섞으면 모호함 주의

# p3-5 | lvalue 와 rvalue, 그리고 값·참조·포인터 | Ch 12.1~12.2
sum: **lvalue** 는 이름이 있고 메모리 위치(주소)가 있는 것, **rvalue** 는 계산하다 잠깐 생긴 임시 값이에요. 함수에 값을 넘기는 방법 세 가지(값, 참조, 포인터)를 이번 회차에서 하나씩 배워요.
ana: 🏠 lvalue는 주소가 있는 집, rvalue는 잠깐 지나가는 택배 상자예요. 집에는 이사 들어갈 수 있지만(대입), 지나가는 상자에는 주소를 붙일 수 없어요.
h: lvalue 와 rvalue
tbl:  | lvalue | rvalue
r: 뜻 | 이름이 있고 주소가 있는 대상 | 계산 중에 잠깐 생긴 값
r: 예 | `x`, `arr[0]` | `5`, `x + 1`, `"abc"`
r: `=` 의 왼쪽에 올 수 있나요 | ✅ | ❌
r: `&` 로 주소를 얻을 수 있나요 | ✅ | ❌
code:
int x { 5 };
x = 10;          // ✅ x 는 lvalue — 왼쪽에 올 수 있어요
// 5 = x;        // ❌ 5 는 rvalue — 잠깐 생긴 값에 대입할 수 없어요
int* p { &x };   // ✅ x 는 주소가 있어요 (포인터는 p3-7에서)
// &(x + 1)      // ❌ x + 1 은 계산 결과일 뿐, 주소가 없어요
:end
p: 이 구분이 중요한 이유는, 다음 파트의 **참조**가 기본적으로 lvalue에만 붙을 수 있기 때문이에요.
h: 함수에 값을 넘기는 세 가지 방법
p: 같은 변수 x를 함수에 넘기는데, 함수 안에서 무엇이 생기는지가 달라요.
tbl: 방법 | 모양 | 함수 안에 생기는 것 | 원본이 바뀔 수 있나요 | “없음”을 표현할 수 있나요
r: 값으로 | `void f(int p)` | x의 **복사본** | ❌ | ❌
r: 참조로 | `void f(int& r)` | x의 **다른 이름**(별명) | ✅ | ❌
r: 포인터로 | `void f(int* q)` | x의 **주소가 적힌 쪽지** | ✅ | ✅ (nullptr)
star: 값 = **복사본**, 참조 = **별명**, 포인터 = **주소 쪽지**.
trap: `5 = x;` > `x = 5;` > 5 같은 임시 값은 `=` 왼쪽에 올 수 없어요
mem: **l**value = **l**ocation(위치)이 있는 것
key: lvalue = 이름과 주소가 있음, rvalue = 임시 값
key: `=` 왼쪽엔 lvalue만
key: 값(복사본) · 참조(별명) · 포인터(주소 쪽지)

# p3-6 | 참조: 변수의 다른 이름 | Ch 12.3~12.6
sum: **참조**(`int&`)는 이미 있는 변수에 붙이는 **또 하나의 이름**이에요. 참조로 바꾸면 원본이 바뀌어요. 함수 매개변수를 참조로 받으면 **복사 없이** 원본을 다룰 수 있어요.
ana: 📛 참조는 별명이에요. “철수”를 “반장”이라고 불러도 같은 사람이고, 반장한테 숙제를 주면 철수가 숙제를 받은 거예요.
h: 참조 기본
code:
#include <iostream>

int main()
{
    int x { 5 };
    int& ref { x };           // ref 는 x 의 다른 이름이에요
    ref = 10;                 // ref 를 바꾸면...
    std::cout << x << '\n';   // x 도 10 — 같은 변수니까요
    return 0;
}
:end
out: 실행 결과
10
:end
tbl: 참조의 규칙 | 예
r: ① 만들 때 반드시 누구의 별명인지 정해야 해요 | `int& r;` ❌
r: ② 한 번 정하면 다른 변수의 별명으로 바꿀 수 없어요 | `ref = y;` 는 “y의 별명이 돼라”가 아니라 “x에 y의 값을 넣어라”
r: ③ 아무것도 아닌 것(널)의 별명은 될 수 없어요 | 
r: ④ 일반 참조는 임시 값(rvalue)에 붙을 수 없어요 | `int& r { 5 };` ❌
r: ⑤ **const 참조**는 임시 값에도 붙을 수 있어요 | `const int& cr { 5 };` ✅
h: 참조로 받는 함수
p: 함수 매개변수를 참조로 받으면, 함수 안에서 바꾼 것이 부른 쪽 원본에 그대로 반영돼요. 1-6에서 원본이 안 바뀌던 문제가 이걸로 해결돼요.
code:
#include <iostream>
#include <string>

void byValue(std::string s) { s += "!"; }   // 복사본에 ! 를 붙임 → 원본 그대로
void byRef(std::string& s)  { s += "!"; }   // 원본에 ! 를 붙임

int main()
{
    std::string msg { "안녕" };
    byValue(msg);
    std::cout << msg << '\n';   // 안녕
    byRef(msg);
    std::cout << msg << '\n';   // 안녕!
    return 0;
}
:end
out: 실행 결과
안녕
안녕!
:end
h: 읽기만 할 거라면 const 참조
p: 큰 문자열이나 vector를 값으로 받으면 통째로 복사돼서 느려요. 바꿀 필요가 없다면 `const std::string&` 처럼 **const 참조**로 받아요. 복사도 없고, 실수로 바꾸는 것도 막고, `"글자"` 같은 임시 값도 받을 수 있어요.
code:
#include <iostream>
#include <string>

void print(const std::string& s)   // 복사 없이 읽기만
{
    std::cout << s << '\n';
    // s += "!";                   // ❌ const 라서 못 바꿔요
}

int main()
{
    std::string name { "홍길동" };
    print(name);
    print("리터럴도 OK");           // const 참조라서 임시 값도 받아요
    return 0;
}
:end
h: 무엇으로 받을까요?
tbl: 상황 | 이렇게 받아요
r: int, double, char, bool 같은 작은 값 | **값** (`int x`) — 복사가 오히려 싸요
r: string, vector 같은 큰 값을 읽기만 | **const 참조** (`const std::string& s`)
r: 문자열을 읽기만 | `std::string_view` 도 좋아요 (2회차)
r: 원본을 바꿔야 함 | **참조** (`std::string& s`)
warn: 부르는 코드 `byRef(msg);` 만 봐서는 msg가 바뀌는지 알 수 없어요. 함수 이름에 의도를 드러내 주는 게 좋아요(예: `appendMark`).
star: 참조는 **반드시 초기화**, **다른 변수로 바꿀 수 없음**, **널 불가**. const 참조는 임시 값도 받아요.
trap: 원본을 바꾸려는데 `void f(std::string s)` > `void f(std::string& s)` > 값으로 받으면 복사본만 바뀌어요
trap: `ref = y;` 로 ref가 y를 가리키게 하려 함 > 참조는 다시 연결할 수 없다는 걸 알기 > x에 y의 값이 대입될 뿐이에요
trap: 큰 문자열을 읽기만 하는데 값으로 받음 > `const std::string&` > 부를 때마다 통째로 복사돼요
mem: **작은 건 값, 큰 건 const 참조, 바꾸려면 참조**
key: 참조 = 변수의 다른 이름, 바꾸면 원본이 바뀌어요
key: 초기화 필수, 다른 변수로 못 바꿈, 널 불가
key: 큰 값을 읽기만 할 땐 const 참조

# p3-7 | 포인터: 주소를 담는 변수 | Ch 12.7~12.11
sum: **포인터**는 다른 변수의 **주소**를 담는 변수예요. `&x` 로 주소를 얻고, `*p` 로 그 주소에 있는 값에 접근해요. 가리킬 게 없으면 **nullptr**, 쓰기 전에는 **널인지 확인**해요.
ana: 📍 포인터는 집 주소가 적힌 쪽지예요. `*p` 는 쪽지에 적힌 집에 찾아가는 것이에요. 빈 쪽지(nullptr)를 들고 찾아가면 길을 잃어요.
h: 기본: 주소 얻기와 따라가기
code:
#include <iostream>

int main()
{
    int x { 5 };
    int* p { &x };               // &x: x 의 주소 / int*: int 를 가리키는 포인터
    std::cout << *p << '\n';     // *p: p 가 가리키는 곳의 값 → 5
    *p = 10;                     // 가리키는 곳(x)에 10 을 넣어요
    std::cout << x << '\n';      // 10
    return 0;
}
:end
out: 실행 결과
5
10
:end
tbl: 기호 | 어디에 쓰나요 | 뜻
r: `int*` | 타입 자리 | “int를 가리키는 포인터”
r: `&x` | 변수 앞 | x의 주소
r: `*p` | 포인터 앞 | p가 가리키는 곳의 값
h: 아무것도 안 가리킬 때: nullptr
p: 포인터가 가리킬 대상이 아직 없으면 `nullptr` 로 만들어 둬요. nullptr인 포인터를 `*` 로 따라가면 미정의 동작(대개 프로그램이 멈춤)이라서, 쓰기 전에 꼭 확인해요.
code:
#include <iostream>

void update(int* p)
{
    if (!p) return;      // 널이면 아무것도 안 하고 돌아가요
    *p = 100;
}

int main()
{
    int x { 5 };
    update(&x);          // x 의 주소를 넘김 → x 가 100 이 돼요
    update(nullptr);     // "가리킬 게 없음"을 넘김 → 그냥 돌아가요
    std::cout << x << '\n';
    return 0;
}
:end
out: 실행 결과
100
:end
p: 부르는 쪽 `update(&x)` 에 `&` 가 보여서 “x가 바뀔 수 있구나”를 알 수 있어요. 그리고 참조와 달리 `nullptr` 로 “없음”을 넘길 수 있어요.
warn: 초기화하지 않은 포인터(`int* p;`)는 널 포인터보다 더 위험해요. 널은 따라가는 순간 바로 멈춰서 찾기 쉽지만, 쓰레기 주소는 엉뚱한 메모리를 조용히 망가뜨려요. 포인터는 항상 `nullptr` 이나 실제 주소로 초기화해요.
h: 포인터와 const — 무엇을 잠그나요?
p: const를 `*` 의 왼쪽에 쓰면 **가리키는 값**을, 오른쪽에 쓰면 **포인터 자신**을 잠가요.
tbl: 선언 | 가리키는 값 바꾸기 (`*p = 10`) | 다른 곳 가리키기 (`p = &y`)
r: `int* p` | ✅ | ✅
r: `const int* p` | ❌ | ✅
r: `int* const p` | ✅ | ❌
r: `const int* const p` | ❌ | ❌
star: const가 `*` **왼쪽이면 값**, **오른쪽이면 포인터**를 잠가요.
trap: `int* p;` 로 만들고 바로 사용 > `int* p { nullptr };` 또는 실제 주소로 초기화 > 쓰레기 주소를 따라가 메모리를 망가뜨려요
trap: 널 검사 없이 `*p = 100;` > `if (!p) return;` 후에 사용 > 널 포인터를 따라가면 미정의 동작이에요
trap: 값을 바꾸려고 `p = 100;` > `*p = 100;` > p는 주소라서 정수를 넣을 수 없어요
mem: `*` 를 벽이라고 생각하면, const가 **왼쪽**이면 값 잠금, **오른쪽**이면 포인터 잠금
key: `&x` 는 주소, `*p` 는 그 주소의 값
key: 가리킬 게 없으면 nullptr, 쓰기 전에 널 확인
key: const 위치: `*` 왼쪽 = 값, 오른쪽 = 포인터

# p3-8 | 댕글링과 값 반환, 참조와 포인터 고르기 | Ch 12.12~12.15
sum: 함수 안의 지역 변수를 **참조나 포인터로 돌려주면 안 돼요**(댕글링). 결과는 **값으로** 돌려주세요. 매개변수는 기본으로 참조, “없음”이 필요할 때만 포인터를 써요.
ana: 🏚️ 댕글링은 이사 간 집의 주소 쪽지예요. 쪽지를 들고 찾아가면 빈집이거나 다른 사람이 살고 있어요.
h: 지역 변수의 참조를 돌려주면
code:
#include <iostream>

int& getBad()
{
    int x { 5 };     // 함수 안에서 만든 지역 변수
    return x;        // x 의 별명(참조)을 돌려줌
}                    // ← 함수가 끝나면 x 는 사라져요

int main()
{
    int& r { getBad() };      // 이미 사라진 x 의 별명
    std::cout << r << '\n';   // ❌ 무엇이 나올지 몰라요 (미정의 동작)
    return 0;
}
:end
p: 함수가 끝나면 지역 변수는 사라져요. 그런데 돌려받은 참조는 여전히 그 자리를 가리키고 있어서 댕글링이 돼요. 해결은 반환형을 `int` 로 바꿔 **값을 복사해서** 돌려주는 거예요.
tbl: 이렇게 돌려주면 | 안전한가요
r: 지역 변수의 참조·주소 | ❌ 댕글링
r: 매개변수로 받은 참조를 그대로 | ✅ 부른 쪽 변수는 아직 살아 있어요
r: 값 (`int`, `std::string`) | ✅ 가장 안전해요
h: 결과가 두 개 이상이면 struct로 묶어 돌려주기
p: 최솟값과 최댓값을 둘 다 돌려주고 싶을 때, 참조 매개변수 두 개로 받아 채우는 방법(out 매개변수)도 있어요. 하지만 부르는 코드만 봐서는 어느 변수가 바뀌는지 알기 어려워요. struct(p3-10)로 묶어서 값으로 돌려주면 더 분명해요.
code:
#include <algorithm>    // std::min_element, std::max_element
#include <iostream>
#include <vector>

struct Stats { int min; int max; };

Stats getStats(const std::vector<int>& data)
{
    return { *std::min_element(data.begin(), data.end()),
             *std::max_element(data.begin(), data.end()) };
}

int main()
{
    std::vector<int> v { 90, 75, 84 };
    Stats s { getStats(v) };
    std::cout << s.min << ' ' << s.max << '\n';
    return 0;
}
:end
out: 실행 결과
75 90
:end
p: `std::min_element` 와 `std::max_element` 는 7회차에서 배우는 표준 알고리즘이에요. 지금은 “가장 작은 값, 가장 큰 값을 찾아 준다”고만 알면 돼요.
h: 참조와 포인터 중 무엇을 쓸까요?
tbl: 상황 | 쓸 것
r: 반드시 있는 대상을 받아요 | **참조** — 널 검사가 필요 없어요
r: 대상이 없을 수도 있어요 | **포인터** — nullptr로 “없음” 표현
r: 큰 객체를 읽기만 해요 | **const 참조**
r: 여러 개를 담아야 해요 | 일단 **std::vector** (6회차)
star: **지역 변수의 참조나 주소를 반환하면 댕글링**이에요. 기본은 참조, “없음”이 필요하면 포인터.
trap: `int& f() { int x { 5 }; return x; }` > `int f() { ... }` 값으로 반환 > 함수가 끝나면 x가 사라져 댕글링이에요
trap: 결과 두 개를 참조 매개변수로 돌려줌 > struct로 묶어 값으로 반환 > 어떤 변수가 바뀌는지 부르는 쪽에서 안 보여요
mem: 댕글링 = **이사 간 집 주소**
key: 지역 변수의 참조·주소는 돌려주지 않기
key: 결과는 값으로, 여러 개면 struct로 묶어서
key: 기본은 참조, 없을 수 있으면 포인터

# p3-9 | enum 과 enum class | Ch 13.1~13.6
sum: **enum** 은 숫자에 이름을 붙이는 타입이에요(빨강=0, 초록=1). 그런데 그냥 enum은 이름이 밖으로 새고 숫자로 몰래 바뀌어서, **enum class** 를 써요.
ana: 🏫 그냥 enum은 문이 없는 교실이에요. 학생 이름이 복도로 새어 나와서 옆 반 학생과 이름이 부딪혀요. enum class는 문 달린 교실이라 `반이름::학생` 으로 불러야 해요.
h: 왜 enum이 필요할까요?
p: 색깔을 `int color { 1 };` 로 저장하면 1이 무슨 색인지 코드만 봐선 알 수 없어요. enum을 쓰면 숫자 대신 이름으로 쓸 수 있어요.
h: 그냥 enum의 문제
code:
#include <iostream>

enum Color { red, green, blue };       // red=0, green=1, blue=2
enum Fruit { apple, banana, cherry };  // apple=0, banana=1, cherry=2

int main()
{
    Color c { red };                   // Color:: 를 안 붙여도 돼요 (이름이 밖으로 새어 있음)
    if (red == apple)                  // 색깔과 과일을 비교하는데 오류가 안 나요
        std::cout << "빨강 == 사과?!\n";
    return 0;
}
:end
out: 실행 결과
빨강 == 사과?!
:end
p: red와 apple은 둘 다 숫자 0으로 바뀌어서 같다고 나와요. 색깔과 과일은 비교할 수 없는 건데, 컴파일러가 막아 주지 못했어요.
tbl: 그냥 enum의 문제 | 결과
r: 이름이 바깥으로 새요 | 다른 enum에 같은 이름(red)이 있으면 충돌해요
r: 숫자로 몰래 바뀌어요 | 서로 다른 enum끼리 비교·대입이 돼요
h: enum class: 문 달린 교실
code:
#include <iostream>

enum class Color { red, green, blue };
enum class Fruit { apple, banana, red };   // red 가 겹쳐도 괜찮아요

int main()
{
    Color c { Color::green };              // 반드시 Color:: 를 붙여요
    // if (c == Fruit::red)                // ❌ 컴파일 오류: 타입이 달라서 비교 불가
    // int n = c;                          // ❌ 숫자로 몰래 바뀌지 않아요
    std::cout << static_cast<int>(c) << '\n';   // 숫자가 필요하면 직접 바꿔요 → 1
    return 0;
}
:end
out: 실행 결과
1
:end
li: 타입 이름은 대문자로 시작하는 게 관례예요(Color, Fruit)
li: 정의 끝에 **`};` 세미콜론**을 꼭 붙여요. 빠뜨리면 엉뚱한 줄에서 오류가 나요
star: enum class는 **`Color::` 를 붙여야** 쓰고, **숫자로 몰래 바뀌지 않아요**. 숫자가 필요하면 `static_cast<int>`.
trap: `enum Color { red };` > `enum class Color { red };` > 이름이 새고, 다른 enum과 비교가 돼 버려요
trap: enum class 값을 바로 `std::cout << c;` > `std::cout << static_cast<int>(c);` > enum class는 숫자로 자동 변환되지 않아요
trap: enum 정의 끝 `;` 를 빠뜨림 > `};` > 다음 줄에서 엉뚱한 오류가 나요
mem: **class** 가 붙으면 문 달린 교실 → `Color::` 로 문을 열고 들어가요
key: 그냥 enum은 이름이 새고 숫자로 바뀌어요
key: enum class는 `Color::red` 처럼 쓰고 다른 타입과 비교 불가
key: 숫자가 필요하면 `static_cast<int>`

# p3-10 | struct: 관련 값을 한 덩어리로 | Ch 13.7~13.12
sum: **struct** 는 이름·번호·월급처럼 함께 다니는 값을 **한 덩어리로 묶는** 타입이에요. `.` 으로 안의 값(멤버)에 접근하고, 포인터라면 **`->`** 를 써요.
ana: 🗂️ struct는 서류철이에요. 직원 한 명의 이름표, 번호표, 월급표를 한 파일에 묶어서 들고 다녀요.
h: 만들고 쓰기
code:
#include <iostream>
#include <string>

struct Employee
{
    int id {};                 // 멤버마다 기본값을 붙여 두면 안전해요
    std::string name {};
    double salary { 0.0 };
};                             // ; 를 잊지 마세요

int main()
{
    Employee e1 { 1, "홍길동", 5000 };           // 멤버를 선언한 순서대로 들어가요
    Employee e2 { 2, "김철수" };                 // 빠진 salary 는 기본값 0
    e1.salary = 6000;                            // . 으로 멤버에 접근해요
    std::cout << e1.name << ' ' << e1.salary << '\n';
    std::cout << e2.name << ' ' << e2.salary << '\n';
    return 0;
}
:end
out: 실행 결과
홍길동 6000
김철수 0
:end
warn: `{ 1, "홍길동", 5000 }` 에서 어떤 값이 어느 멤버로 가는지는 **struct 안에 멤버를 적은 순서**로만 정해져요. 나중에 멤버 순서를 바꾸면 기존 코드가 조용히 다른 뜻이 돼요. C++20의 `{ .id = 1, .name = "홍길동" }` 처럼 이름을 붙여 넣으면 안전해요.
h: 함수에 넘기기, 포인터로 접근하기
code:
#include <iostream>
#include <string>

struct Employee { int id {}; std::string name {}; };

void print(const Employee& e)          // 큰 struct는 const 참조로 받아요
{
    std::cout << e.id << ": " << e.name << '\n';
}

int main()
{
    Employee e { 1, "홍길동" };
    print(e);

    Employee* p { &e };                // e 를 가리키는 포인터
    std::cout << p->name << '\n';      // 포인터로 멤버에 접근할 땐 ->
    std::cout << (*p).name << '\n';    // 같은 뜻 (괄호 필수) — 보통 -> 를 써요
    return 0;
}
:end
out: 실행 결과
1: 홍길동
홍길동
홍길동
:end
h: struct 크기는 멤버 크기의 합보다 클 수 있어요
p: CPU는 8바이트짜리 값을 8의 배수 주소에서 읽을 때 가장 빨라요. 그래서 컴파일러가 멤버 사이에 빈칸(패딩)을 끼워 넣어요. 큰 멤버를 먼저 적으면 빈칸이 줄어요.
tbl: struct | 멤버 순서 | sizeof (일반적인 64비트)
r: BadOrder | char, double, char | **24** (1 + 빈칸7 + 8 + 1 + 빈칸7)
r: GoodOrder | double, char, char | **16** (8 + 1 + 1 + 빈칸6)
star: 포인터로 멤버에 접근할 땐 **`p->name`** (= `(*p).name`). struct 크기는 **패딩** 때문에 멤버 합보다 클 수 있어요.
trap: 포인터인데 `p.name` > `p->name` > p는 주소라서 `.` 을 쓸 수 없어요
trap: struct 멤버 순서를 바꿈 > 지정 초기화 `{ .id = 1, .name = "홍" }` > 순서대로 넣던 기존 초기화가 조용히 다른 뜻이 돼요
trap: struct 정의 끝 `;` 를 빠뜨림 > `};` > 엉뚱한 줄에서 오류가 나요
mem: `->` = 화살표를 따라가서 그 안의 멤버
key: struct = 관련 값 묶음, `.` 으로 멤버 접근
key: 포인터면 `->`, 함수엔 const 참조로 넘기기
key: 패딩 때문에 큰 멤버부터 적으면 크기가 줄어요

# p3-11 | 매개변수 고르는 법과 3회차 함정 정리 | Ch 10~13
sum: 매개변수 타입은 **① 원본을 바꾸나? → ② 없을 수도 있나? → ③ 복사가 비싼가? → ④ 문자열인가?** 순서로 물어보면 정할 수 있어요.
ana: 🧭 갈림길 안내판 네 개를 위에서부터 차례로 보고, “예”가 나오는 첫 번째 길로 가면 돼요.
h: 네 가지 질문
flow: ① 원본을 바꿔야 하나요? > 예 → 참조 `T&` || ② 대상이 없을 수도 있나요? > 예 → 포인터 `T*` || ③ 복사가 비싼가요? > int·double 같은 작은 값 → 값 `T` / 그 외 → `const T&` || ④ 문자열을 읽기만 하나요? > 예 → `std::string_view`
code:
void tick(int count);                     // 작은 값, 읽기만 → 값
void normalize(std::vector<double>& v);   // 원본을 바꿈 → 참조
void print(const Employee& e);            // 큰 객체를 읽기만 → const 참조
void log(std::string_view msg);           // 문자열을 읽기만 → string_view
void attach(Node* parent);                // 부모가 없을 수도 있음 → 포인터
:end
tip: 왜 이렇게 받았는지 주석 한 줄을 남겨 두면, 나중에 고칠 때 실수가 줄어요.
h: 3회차 함정 정리
p: 아래 함정 카드에 3회차에서 자주 틀리는 9가지를 모았어요. 각 줄의 ❌와 ✅를 비교하면서 왜 틀렸는지 한 번씩 소리 내어 읽어 보세요.
trap: `int i` 와 `v.size()` 를 비교 `i < v.size()` > 범위 기반 for 또는 `std::ssize(v)` > 부호 있는 수와 없는 수를 섞게 돼요
trap: `for (auto e : v)` 로 큰 원소 읽기 > `for (const auto& e : v)` > 원소마다 복사돼요
trap: 지역 변수의 참조·주소 반환 > 값으로 반환 > 함수가 끝나면 사라져서 댕글링이에요
trap: 템플릿 정의를 .cpp 에 둠 > 정의까지 헤더에 (5회차) > 링크 오류가 나요
trap: `enum Color { red };` > `enum class Color { red };` > 이름이 새고 숫자로 몰래 비교돼요
trap: 널 검사 없이 `*p` > `if (p)` 로 먼저 확인 > 널을 따라가면 미정의 동작
trap: `(double)a / b` > `static_cast<double>(a) / b` > 어떤 변환인지 안 보여요
trap: struct 멤버 순서 변경 > 지정 초기화 사용 > 기존 초기화의 뜻이 조용히 바뀌어요
trap: struct·enum 정의 끝 `;` 누락 > `};` > 엉뚱한 곳에서 오류가 나요
star: 매개변수 결정 순서 **바꾸나 → 없을 수 있나 → 비싼가 → 문자열인가**.
mem: **변·없·비·문** (변경? 없음? 비싼가? 문자열?)
key: 바꾸면 `&`, 없을 수 있으면 `*`, 크면 `const&`, 문자열은 `string_view`
key: `for (const auto& e : v)` 로 복사 피하기
key: 함정 9개는 함정 카드로 복습
