# p6-1 | std::vector 시작하기 | Ch 16.1~16.3, 16.6
sum: 몇 개가 들어올지 모를 때는 **std::vector** 를 써요. 필요한 만큼 **알아서 늘어나고**, 지금 몇 개 들어 있는지 **스스로 기억**해요.
ana: 🎒 vector는 늘어나는 가방이에요. 물건을 넣을수록 알아서 커지고, 몇 개 들었는지도 가방이 기억해요.
h: 배열의 문제부터
code:
int scores[100] {};       // 학생이 3명이면 97칸 낭비, 101명이면 넘쳐요
int count { 0 };          // 개수는 따로 기억해야 해요
:end
p: 배열은 크기를 미리 정해야 해서, 작게 잡으면 넘치고 크게 잡으면 낭비예요. 그리고 4회차에서 봤듯이 개수를 따로 들고 다니다가 잘못 넘기면 조용히 틀린 답이 나와요.
fix: PPT 주석의 “3명만 오면 397칸 낭비”는 100칸 배열이므로 **97칸**이 맞아요.
h: vector 기본 사용법
code:
#include <iostream>
#include <vector>          // vector 를 쓰려면 꼭 include

int main()
{
    std::vector<int> scores { 90, 75, 84 };      // int 를 담는 vector, 처음에 세 개

    std::cout << scores.size() << '\n';          // 3 — 지금 몇 개
    std::cout << scores[0] << '\n';              // 90 — 첫 번째 (번호는 0부터)
    scores.push_back(68);                        // 맨 뒤에 하나 추가
    std::cout << scores.size() << ' ' << scores.back() << '\n';   // 4 68 — 개수와 마지막 원소
    return 0;
}
:end
out: 실행 결과
3
90
4 68
:end
tbl: 코드 | 뜻
r: `std::vector<int>` | int를 담는 vector. `< >` 안에 담을 타입을 적어요 (5회차의 클래스 템플릿)
r: `v.size()` | 지금 들어 있는 개수
r: `v[i]` | i번째 원소 (**0부터** 세요)
r: `v.push_back(x)` | 맨 뒤에 x 추가
r: `v.back()` | 맨 마지막 원소
h: 몇 개가 올지 몰라도 그냥 담기
code:
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> scores {};              // 빈 vector 로 시작
    int x {};
    while (std::cin >> x && x >= 0)          // 음수를 입력하면 끝
        scores.push_back(x);                 // 들어오는 대로 뒤에 붙여요
    std::cout << scores.size() << "개 담김\n";
    return 0;
}
:end
out: 입력: 90 75 84 68 -1
4개 담김
:end
tip: vector를 쓰는 가장 큰 이유는 “최대 몇 개를 담지?”, “넘치면 어쩌지?” 같은 고민이 통째로 사라진다는 거예요.
term: 컨테이너 | container | 같은 타입의 값을 여러 개 담는 타입. vector가 가장 많이 쓰여요
star: `std::vector<int>` 의 `<int>` 는 **담을 타입**이에요. 번호는 **0부터** 세요.
trap: 크기를 넉넉히 잡은 배열 + 개수 변수 > `std::vector` > 개수를 잘못 넘겨도 아무도 몰라요
trap: 첫 번째 원소를 `v[1]` 로 읽음 > `v[0]` > 번호는 0부터예요
mem: vector = **늘어나는 가방**
key: 개수를 모르면 std::vector
key: `size()` · `v[i]` · `push_back()` · `back()`
key: 번호는 0부터

# p6-2 | { } 와 ( ), [] 와 at(), size() 의 함정 | Ch 16.2~16.3
sum: vector는 괄호 모양에 따라 뜻이 달라요. **`{3}` 은 원소 3 하나**, **`(3)` 은 0이 세 칸**. `v[i]` 는 범위를 검사하지 않고, `v.at(i)` 는 검사해요. `size()` 는 부호 없는 수예요.
ana: 🛒 `{3}` 은 장바구니에 “3”이라는 물건 하나를 담은 거고, `(3)` 은 빈칸 세 개짜리 장바구니를 받은 거예요.
h: 괄호에 따라 완전히 달라요
code:
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> a { 3 };       // 원소 3 하나
    std::vector<int> b ( 3 );       // 0 이 세 칸
    std::vector<int> c { 3, 5 };    // 원소 3, 5 두 개
    std::vector<int> d ( 3, 5 );    // 5 가 세 칸
    std::cout << a.size() << ' ' << b.size() << ' ' << c.size() << ' ' << d.size() << '\n';
    return 0;
}
:end
out: 실행 결과
1 3 2 3
:end
tbl: 쓴 것 | 크기 | 내용
r: `{ 3 }` | 1 | 3
r: `( 3 )` | 3 | 0 0 0
r: `{ 3, 5 }` | 2 | 3 5
r: `( 3, 5 )` | 3 | 5 5 5
p: 규칙은 하나예요. 값을 **나열**할 땐 `{ }`, “**몇 칸짜리로**” 만들 땐 `( )`. “초기화는 중괄호”라는 1회차 규칙의 유일한 예외예요.
h: [] 와 at() 의 차이
p: 3칸짜리 vector에서 10번 칸을 읽으면 어떻게 될까요?
tbl:  | `v[10]` | `v.at(10)`
r: 범위 검사 | ❌ 안 해요 | ✅ 해요
r: 범위 밖이면 | 엉뚱한 메모리를 읽고 계속 실행 (미정의 동작) | 즉시 멈추고 `std::out_of_range` 오류를 알려 줘요
r: 속도 | 조금 빨라요 | 검사하는 만큼 아주 조금 느려요
r: 언제 쓸까요 | 범위가 확실할 때 | **배우는 동안**, 범위가 확실하지 않을 때
p: `v[10]` 은 오류 없이 이상한 숫자를 읽고 프로그램이 계속 돌아서 버그를 찾기 어려워요. `at()` 은 바로 멈춰서 어디가 잘못됐는지 알려 줘요.
h: size() 는 부호 없는 수예요
p: `size()` 는 음수가 없는 정수(size_t)를 돌려줘요. 그래서 3회차에서 본 “부호 섞기” 문제가 여기서 자주 생겨요.
code:
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v {};                  // 비어 있어요
    std::cout << v.size() - 1 << '\n';      // 0 - 1 인데...
    return 0;
}
:end
out: 실행 결과 (64비트 환경)
18446744073709551615
:end
p: 0 − 1이 −1이 아니라 엄청 큰 수가 됐어요. 그래서 `for (int i = 0; i < v.size() - 1; ++i)` 같은 코드는 빈 vector에서 거의 끝없이 돌아요.
tbl: vector를 훑는 방법 | 어떤가요
r: `for (int x : v)` (범위 기반 for, 다음 파트) | ✅ 가장 좋아요. 번호가 없어서 부호 문제도, 범위 밖 문제도 없어요
r: `for (std::size_t i = 0; i < v.size(); ++i)` | ✅ 부호 없는 타입으로 맞춰서 세기
r: `for (int i = 0; i < v.size(); ++i)` | ⚠️ 부호 섞기 경고
star: `{3}` 은 **원소 하나**, `(3)` 은 **세 칸**. `[]` 는 검사 안 함, `at()` 은 검사함.
trap: 3칸을 원하면서 `std::vector<int> v { 3 };` > `std::vector<int> v ( 3 );` > 원소 3 하나짜리가 돼요
trap: 범위 밖 `v[10]` > `v.at(10)` > 검사 없이 엉뚱한 값을 읽어요 (미정의 동작)
trap: 빈 vector에서 `v.size() - 1` > `v.empty()` 로 먼저 확인 > 0 − 1이 거대한 수가 돼요
mem: **소**괄호 = **수**량(칸 수), **중**괄호 = **줄**줄이 값 나열
key: `{3}` 원소 하나, `(3)` 세 칸
key: `[]` 검사 X, `at()` 검사 O
key: size()는 부호 없는 수 → 범위 기반 for로 피하기

# p6-3 | 크기 바꾸기와 범위 기반 for | Ch 16.6~16.8
sum: `push_back`, `pop_back`, `resize`, `clear` 로 크기를 바꿔요. 원소를 하나씩 볼 때는 **범위 기반 for** 를 쓰고, 읽기만 하면 **`const T&`**, 고치려면 **`T&`** 로 받아요.
ana: 📸 `for (T x : v)` 는 사진을 복사해서 낙서하는 거라 원본은 그대로예요. `for (T& x : v)` 는 원본 사진에 직접 낙서하는 거예요.
h: 크기 바꾸는 함수들
code:
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v { 1, 2, 3 };
    v.push_back(4);                         // 1 2 3 4  — 뒤에 추가
    v.pop_back();                           // 1 2 3    — 뒤에서 하나 빼기
    v.resize(5);                            // 1 2 3 0 0 — 5칸으로 (늘어난 칸은 0)
    std::cout << v.size() << '\n';
    v.clear();                              // 전부 비우기
    std::cout << std::boolalpha << v.empty() << '\n';   // 비었나요? → true
    return 0;
}
:end
out: 실행 결과
5
true
:end
h: 범위 기반 for: 하나씩 꺼내 보기
p: `for (타입 이름 : vector)` 라고 쓰면 원소를 처음부터 끝까지 하나씩 꺼내 줘요. 번호(i)를 쓰지 않아서 범위를 벗어나거나 부호를 섞는 실수가 원천적으로 없어요.
code:
#include <iostream>
#include <string>
#include <vector>

int main()
{
    std::vector<std::string> names { "홍길동", "김철수" };

    for (std::string s : names)          // ① 값으로: 원소마다 복사본 s
        s += "님";                        //    복사본에만 붙어요
    std::cout << names[0] << '\n';       // 홍길동 — 원본 그대로

    for (std::string& s : names)         // ② 참조로: s 는 원소의 별명
        s += "님";                        //    원본에 붙어요
    std::cout << names[0] << '\n';       // 홍길동님

    for (const std::string& s : names)   // ③ const 참조로: 복사 없이 읽기만
        std::cout << s << ' ';
    std::cout << '\n';
    return 0;
}
:end
out: 실행 결과
홍길동
홍길동님
홍길동님 김철수님
:end
tbl: 쓰는 법 | 언제 | 복사
r: `for (const T& x : v)` | 읽기만 할 때 — **기본** | 없어요
r: `for (T& x : v)` | 원소를 고칠 때 | 없어요
r: `for (T x : v)` | int, double 같은 작은 타입을 읽을 때 | 매번 복사
p: 3회차에서 배운 “값 / 참조 / const 참조” 규칙이 그대로 적용돼요.
star: 원소를 고치려면 **`&`** 를 꼭 붙여요. 빼먹으면 복사본만 바뀌고 오류도 안 나요.
trap: 원소를 고치려는데 `for (std::string s : names)` > `for (std::string& s : names)` > 복사본만 바뀌어요
trap: 큰 타입을 `for (std::string s : v)` 로 읽기만 > `for (const std::string& s : v)` > 원소마다 복사돼요
mem: `&` 없음 = **복사본에 낙서**, `&` 있음 = **원본에 낙서**
key: push_back · pop_back · resize · clear · empty
key: 읽기 `const T&`, 고치기 `T&`, 작은 타입만 `T`
key: `&` 없이 고치면 원본은 안 바뀌어요

# p6-4 | vector 의 메모리, 함수에 넘기기, 클래스 담기 | Ch 16.2, 16.5
sum: vector 변수 자체는 **원소가 어디 있는지 적힌 작은 정보**(보통 24바이트)이고, 원소는 다른 곳(힙)에 있어요. 함수에는 **const 참조**로 넘기고, 돌려줄 때는 **값으로** 돌려줘요. 내가 만든 클래스도 담을 수 있어요.
ana: 🗺️ vector 변수는 창고 위치가 적힌 지도 한 장이에요. 물건(원소)은 멀리 있는 창고에 있어요. 지도는 작으니까 물건이 백만 개여도 지도 크기는 같아요.
h: vector 변수의 크기는 원소 수와 상관없어요
code:
#include <array>
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v(1000);           // int 1000개
    std::array<int, 1000> a {};         // int 1000개 (다음 파트)
    std::cout << sizeof(v) << '\n';     // vector 변수 자체의 크기
    std::cout << sizeof(a) << '\n';     // array 는 원소를 자기 안에 통째로 가져요
    return 0;
}
:end
out: 실행 결과 (일반적인 64비트 환경)
24
4000
:end
p: vector 변수 안에는 “원소가 시작하는 곳, 끝나는 곳, 확보한 공간의 끝”을 가리키는 포인터 세 개 정도만 있어요. 원소는 따로 잡은 메모리(힙)에 있어서 개수를 늘릴 수 있어요.
h: 함수에 넘기기
tbl: 원소 10만 개짜리 vector | 무슨 일이 생기나요
r: `void f(std::vector<int> v)` (값으로) | ❌ 원소 10만 개를 통째로 복사해요 (약 400KB)
r: `void f(const std::vector<int>& v)` | ✅ 복사 없이 원본을 읽어요
r: `std::vector<int> make()` (값으로 돌려주기) | ✅ C++17부터 돌려줄 때 복사하지 않아요
p: “큰 걸 돌려주면 느리다”는 건 옛날 얘기예요. 함수 안에서 만든 vector는 그냥 값으로 돌려주면 돼요.
h: 내가 만든 클래스를 담기
code:
#include <iostream>
#include <string>
#include <string_view>
#include <vector>

class Student {
    std::string m_name {};
    int m_score {};
public:
    Student(std::string_view n, int s) : m_name { n }, m_score { s } { }
    const std::string& name() const { return m_name; }
    int score() const { return m_score; }
};

int main()
{
    std::vector<Student> roster {};
    roster.push_back(Student { "홍길동", 90 });   // 객체를 만들어서 넣기
    roster.push_back(Student { "김철수", 75 });
    roster.emplace_back("이영희", 84);            // 생성자 인자만 넘기면 vector 안에서 바로 만들어요

    for (const Student& st : roster)
        std::cout << st.name() << " (" << st.score() << "점)\n";
    return 0;
}
:end
out: 실행 결과
홍길동 (90점)
김철수 (75점)
이영희 (84점)
:end
tbl: 함수 | 차이
r: `push_back(Student { ... })` | 바깥에서 만든 객체를 vector 안으로 옮겨 넣어요
r: `emplace_back("이영희", 84)` | 생성자 인자를 받아 vector 안에서 바로 만들어요. 한 단계 덜 해요
fix: PPT 코드에는 김철수를 넣는 줄이 없는데 출력에는 김철수가 있어서, 그 줄을 보충했어요.
p: vector가 사라질 때는 vector의 소멸자가 담긴 원소들의 소멸자까지 불러 줘요. 5회차의 RAII 그대로예요.
star: `sizeof(vector)` 는 **원소 수와 상관없이** 일정해요. 함수엔 **const 참조**, 돌려줄 땐 **값**.
trap: 큰 vector를 값으로 넘김 `void f(std::vector<int> v)` > `void f(const std::vector<int>& v)` > 통째로 복사돼요
trap: 반환이 느릴까 봐 vector를 참조 매개변수로 채워서 돌려줌 > 그냥 값으로 반환 > C++17부터 반환할 때는 복사하지 않아요
mem: vector = **창고 지도** (지도는 작고 물건은 창고에)
key: 원소는 힙에, vector 변수는 작은 관리 정보
key: 넘길 땐 const 참조, 돌려줄 땐 값
key: `emplace_back` 은 생성자 인자로 안에서 바로 만들어요

# p6-5 | 지우기, 용량, 그리고 옛 주소가 무효가 되는 문제 | Ch 16.6~16.7
sum: vector에는 **size(지금 원소 수)** 와 **capacity(옮기지 않고 담을 수 있는 수)** 가 따로 있어요. capacity가 모자라면 vector가 **원소 전체를 더 큰 곳으로 옮겨서**, 예전에 기억해 둔 주소가 무효가 돼요.
ana: 🪑 size는 앉아 있는 사람 수, capacity는 의자 수예요. 의자가 모자라면 더 큰 방으로 **전원 이사**를 가요. 옛 방 주소로 찾아가면 아무도 없어요.
h: 지우기, 복사, 비교
code:
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> a { 1, 2, 3, 4 };
    a.erase(a.begin() + 1);          // 두 번째 원소(2)를 지워요 → 1 3 4 (뒤가 한 칸씩 당겨져요)
    a.pop_back();                    // 마지막(4)을 지워요 → 1 3

    std::vector<int> b { a };        // a 를 통째로 복사 → 서로 남남
    b[0] = 99;                       // b 만 바뀌어요
    std::vector<int> c { 1, 3 };
    std::cout << a[0] << ' ' << b[0] << ' ' << std::boolalpha << (a == c) << '\n';
    return 0;
}
:end
out: 실행 결과
1 99 true
:end

# p6-7 | C 스타일 배열과 C 문자열 | Ch 17.7~17.10
sum: C 시절부터 있던 배열(`int arr[5]`)은 멤버 함수도 범위 검사도 없고, **함수에 넘기면 크기 정보를 잃어요**(배열 감쇠). 새로 쓸 일은 거의 없지만 **읽을 줄은** 알아야 해요.
ana: 🧳 C 배열이 함수의 문을 지나가면 짐(크기 정보)을 두고 **주소가 적힌 쪽지만** 들고 들어가요.
h: C 배열 기본
code:

int main()
{
    int arr[5] { 1, 2, 3, 4, 5 };
    std::cout << arr[0] << '\n';                          // 1
    std::cout << sizeof(arr) / sizeof(arr[0]) << '\n';    // 5 — 전체 크기 ÷ 원소 하나 크기
    // arr.size();                                        // ❌ C 배열에는 멤버 함수가 없어요
    return 0;
}
:end

1
5
:end

r: 범위 검사 | 없어요 | `at()` 이 있어요
r: 함수에 넘기면 | **크기를 잃어요** | 크기가 그대로 따라가요
h: 함정: 함수에 넘기면 크기를 잃어요

}

int main()
{
    int arr[5] {};
    std::cout << "main 안: " << sizeof(arr) << '\n';   // 배열 전체 크기

trap: 함수 안에서 `sizeof(arr) / sizeof(arr[0])` 로 개수 계산 > 개수를 따로 넘기거나 std::array·vector 사용 > 포인터 크기로 계산돼서 틀려요
trap: C 문자열 끝 `\0` 을 빠뜨림 > std::string 사용 > 끝을 몰라 계속 읽어 나가요

# p6-9 | 정리: vector로 다시 쓴 명단, 6회차 함정 모음 | Ch 16~17
sum: 4회차의 “배열 두 개 + 개수” 명단을 **vector 하나**로 바꾸면, 개수를 따로 들고 다닐 일이 없어서 **49.8 버그가 아예 생길 수 없어요**.

h: vector로 다시 쓴 Roster
code:
#include <iostream>
#include <string>
#include <string_view>
#include <vector>

class Student {
    std::string m_name {};
    int m_score {};
public:
    Student(std::string_view n, int s) : m_name { n }, m_score { s } { }
    int getScore() const { return m_score; }
};

class Roster {
    std::vector<Student> m_list {};
public:
    void add(std::string_view n, int s) { m_list.emplace_back(n, s); }
    double average() const
    {
        if (m_list.empty()) return 0.0;              // 비었으면 0으로 나누지 않게
        int sum { 0 };
        for (const Student& st : m_list) sum += st.getScore();
        return static_cast<double>(sum) / static_cast<double>(m_list.size());
    }
};

int main()
{
    Roster r {};
    r.add("홍길동", 90);
    r.add("김철수", 75);
    r.add("이영희", 84);
    std::cout << r.average() << '\n';
    return 0;
}
:end
out: 실행 결과
83
:end
p: average()에 개수를 넘기지 않아요. vector가 자기 크기를 알고 있으니까요. 그래서 4회차처럼 개수를 잘못 넘겨 49.8이 나오는 일이 구조적으로 불가능해요.
