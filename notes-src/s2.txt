# p2-1 | const 와 숫자 쓰는 법 | Ch 5.1~5.3
sum: **const** 를 붙이면 “처음 넣은 값을 다시는 못 바꾸는” 변수가 돼요. 숫자 앞에 0을 붙이면 **8진수**로 읽히니 조심해요.
ana: 🔒 const는 값에 거는 자물쇠예요. 처음 값을 넣을 때만 열려 있고, 그다음부터는 잠겨요.
h: const 쓰는 법
p: 프로그램 안에서 절대 바뀌면 안 되는 값(중력 가속도, 최대 인원 등)에 const를 붙여 두면, 실수로 바꾸는 코드를 컴파일러가 막아 줘요.
code:
#include <iostream>

int main()
{
    const double gravity { 9.8 };   // const 변수는 만들 때 반드시 값을 넣어야 해요
    // gravity = 10.0;              // ❌ 컴파일 오류: const 는 바꿀 수 없어요

    int input {};
    std::cin >> input;
    const int rows { input };       // ✅ 실행 중에 정해진 값도 const 로 묶을 수 있어요
    std::cout << gravity * rows << '\n';
    return 0;
}
:end
out: 입력 2
19.6
:end
p: 두 번째 const를 보세요. const의 약속은 “**한 번 넣으면 안 바뀐다**”뿐이라서, 넣는 값이 실행 중에 정해져도 괜찮아요. 컴파일할 때 이미 값이 정해져야 한다면 다음 파트의 **constexpr** 을 써요.
h: 숫자를 쓰는 여러 방법
tbl: 이렇게 쓰면 | 이런 뜻이에요
r: `3.14` | double (실수의 기본)
r: `3.14f` | float (끝에 f)
r: `5u` | unsigned int
r: `0b1010` | 2진수 → 10
r: `012` | ⚠️ **8진수** → 10 (12가 아니에요!)
r: `0xFF` | 16진수 → 255
r: `1'000'000` | 그냥 1000000. `'` 는 읽기 편하라고 넣는 구분자
warn: 날짜처럼 자릿수를 맞추려고 `int month { 08 };` 이라고 쓰면 컴파일 오류가 나요. 0으로 시작해서 8진수가 됐는데, 8진수에는 8이라는 숫자가 없거든요. `07` 은 오류 없이 7이 되지만, `010` 은 조용히 8이 돼요.
star: `012` 는 **10**, `0xFF` 는 **255** 예요.
trap: 자릿수를 맞추려고 `int day { 09 };` > `int day { 9 };` > 0으로 시작하면 8진수라서 9는 오류예요
trap: const 변수를 만들고 나중에 값을 넣으려 함 `const int x; x = 5;` > `const int x { 5 };` > const는 만들 때 값을 넣어야 해요
mem: 0**b** = **b**inary(2진), 0**x** = he**x**(16진), 그냥 **0** = 8진수 (O ctal의 O 모양)
key: const = 처음 넣은 값을 못 바꿔요 (실행 중 값도 OK)
key: `012` 는 8진수 10, `0xFF` 는 255
key: `3.14` 는 double, `3.14f` 는 float

# p2-2 | constexpr: 컴파일할 때 정해지는 상수 | Ch 5.4~5.6
sum: **constexpr** 은 값이 **컴파일할 때 이미 정해지는** 상수예요. 미리 아는 값(9.8, 100 같은)에는 const보다 constexpr을 기본으로 써요.
ana: 📅 const는 “오늘 정하면 그다음엔 안 바꿀게”예요. constexpr은 “달력에 이미 **인쇄돼 있어**”예요.
h: const와 무엇이 다를까요?
p: const는 값이 실행 중에 정해져도 되지만, constexpr은 컴파일러가 컴파일하는 동안 값을 계산할 수 있어야 해요. 그래서 키보드로 입력받은 값으로는 constexpr을 만들 수 없어요.
code:
#include <iostream>

int main()
{
    constexpr int side { 4 };
    constexpr int area { side * side };   // 컴파일할 때 16으로 계산돼요
    int arr[area] {};                     // 배열 크기처럼 "컴파일할 때 알아야 하는 자리"에 쓸 수 있어요

    int input {};
    std::cin >> input;
    // constexpr int r { input };         // ❌ 오류: 입력값은 실행해야 알 수 있어요
    const int r { input };                // ✅ const는 OK
    std::cout << area + r << '\n';
    return 0;
}
:end
out: 입력 4
20
:end
tbl:  | const | constexpr
r: 값이 정해지는 때 | 실행 중이어도 OK | **반드시 컴파일할 때**
r: 값을 바꿀 수 있나요 | ❌ | ❌ (constexpr은 자동으로 const)
r: 배열 크기로 쓰기 | 실행 중에 정해진 값이면 ❌ | ✅
r: 언제 쓰나요 | 값이 실행 중에 정해질 때 | 미리 아는 값 — **기본으로 이쪽**
fix: 엄밀하게는 `const int n { 5 };` 처럼 **숫자로 바로 초기화한 const 정수**는 배열 크기에도 쓸 수 있어요. 헷갈리면 “컴파일할 때 필요한 상수 = constexpr”로 기억하면 돼요.
ref: 컴파일러는 결과만 같다면 코드를 자유롭게 최적화할 수 있어요(as-if 규칙). 그래서 const도 컴파일할 때 계산될 수 있지만, 그게 **보장**되는 건 constexpr뿐이에요.
star: constexpr은 **컴파일할 때 값이 정해져야** 해요. 실행 중 값(입력 등)으로 만들면 컴파일 오류예요.
trap: `constexpr int r { input };` (input은 입력받은 값) > `const int r { input };` > 입력값은 실행해야 알 수 있어서 constexpr이 될 수 없어요
mem: const = “안 바꿀게”, constexpr = “**이미 알아**”
key: constexpr = 컴파일할 때 정해지는 상수
key: constexpr은 자동으로 const이기도 해요
key: 미리 아는 값은 constexpr이 기본

# p2-3 | std::string 과 한 줄 입력 | Ch 5.7
sum: 글자를 여러 개 담을 때는 **std::string** 을 써요. `std::cin >>` 은 **띄어쓰기에서 끊기기** 때문에, 공백이 들어간 한 줄은 `std::getline(std::cin >> std::ws, 변수)` 로 받아요.
ana: ✂️ `cin >>` 은 띄어쓰기마다 가위로 잘라요. “홍 길동”을 넣으면 “홍”만 가져가고 “길동”은 바닥에 남겨 둬요.
h: std::string 기본
code:
#include <iostream>
#include <string>    // std::string 을 쓰려면 꼭 include

int main()
{
    std::string name { "홍길동" };
    name += "님";                         // 뒤에 글자를 붙이면 길이가 알아서 늘어나요
    std::cout << name << '\n';
    std::cout << name.length() << '\n';   // 길이 — 글자 수가 아니라 "바이트" 수예요
    return 0;
}
:end
out: 실행 결과 (UTF-8 환경)
홍길동님
12
:end
p: 마지막 줄을 보세요. 글자는 4개인데 12가 나왔어요. `length()` 는 바이트 수를 세는데, 한글 한 글자는 3바이트라서 4 × 3 = 12가 돼요.
h: 공백이 있는 이름 받기
p: `std::cin >> name` 은 공백을 만나면 거기서 멈춰요. 공백까지 포함해 한 줄 전체를 받으려면 `std::getline` 을 써요.
code:
#include <iostream>
#include <string>

int main()
{
    std::string name {};
    std::cout << "이름: ";
    std::getline(std::cin >> std::ws, name);   // 한 줄 전체를 name에
    std::cout << name << "님 안녕하세요\n";
    return 0;
}
:end
out: 입력: 홍 길동
이름: 홍 길동님 안녕하세요
:end
tbl: 코드 조각 | 뜻
r: `std::getline(입력, 변수)` | 줄바꿈(Enter) 전까지 한 줄 전체를 변수에 넣어요
r: `std::cin >> std::ws` | 입력 앞쪽에 남아 있는 공백·줄바꿈을 먼저 버려요
h: std::ws 는 왜 붙여야 할까요?
p: 앞에서 `std::cin >> age;` 로 숫자를 읽었다면, 사용자가 누른 Enter(줄바꿈)는 읽히지 않고 남아 있어요. 그 상태에서 `std::getline(std::cin, s)` 를 하면, 남아 있던 줄바꿈을 바로 만나서 **빈 문자열**을 읽고 끝나 버려요. `std::ws` 가 그 줄바꿈을 먼저 치워 줘요.
code:
int age {};
std::string name {};
std::cin >> age;                          // 20 입력 후 Enter → Enter가 남아 있어요
std::getline(std::cin, name);             // ❌ 남은 Enter를 읽고 끝 → name은 빈 문자열
std::getline(std::cin >> std::ws, name);  // ✅ 남은 Enter를 치우고 다음 줄을 읽어요
:end
star: 공백이 있는 한 줄 입력은 `std::getline(std::cin >> std::ws, s)` — **ws까지 세트로** 외워요.
trap: `std::cin >> name;` 으로 “홍 길동” 받기 > `std::getline(std::cin >> std::ws, name);` > 공백에서 끊겨 “홍”만 들어가요
trap: `cin >> age;` 바로 다음에 `getline(cin, s);` > `getline(cin >> ws, s);` > 남아 있던 Enter 때문에 빈 문자열이 읽혀요
mem: **ws** = **w**hite **s**pace(공백) 청소기
key: 글자 여러 개는 std::string, `<string>` include
key: `length()` 는 바이트 수 (한글 1글자 = 3바이트)
key: 한 줄 입력 = `std::getline(std::cin >> std::ws, s)`

# p2-4 | std::string_view: 복사 없이 보기만 | Ch 5.8~5.9
sum: **std::string_view** 는 문자열을 **복사하지 않고 들여다보는 창문**이에요. 빠르지만, 창문 너머의 원래 문자열이 사라지면 아무것도 안 보여요.
ana: 🪟 string_view는 창문이에요. 집(원래 문자열)을 통째로 옮겨 오는 대신 창문으로 보기만 해요. 그런데 집이 철거되면 창문으로 보이는 건 허공이에요.
h: 왜 필요할까요?
p: 함수에 `std::string` 을 그냥 넘기면 매번 문자열 전체가 **복사**돼요. 읽기만 할 거라면 복사는 낭비예요. string_view는 “어디서부터 몇 글자”라는 정보만 가지고 원래 문자열을 그대로 들여다봐요.
code:
#include <iostream>
#include <string>
#include <string_view>

void greet(std::string_view name)   // 복사 없이 보기만 해요
{
    std::cout << name << "님 안녕하세요\n";
}

int main()
{
    std::string n { "홍길동" };
    greet(n);          // std::string 을 넘겨도 되고
    greet("김철수");    // 따옴표 글자를 바로 넘겨도 돼요
    return 0;
}
:end
out: 실행 결과
홍길동님 안녕하세요
김철수님 안녕하세요
:end
tbl:  | std::string | std::string_view
r: 하는 일 | 문자열을 **가지고** 있어요 | 남의 문자열을 **보기만** 해요
r: 넘길 때 복사 | 전체 복사 | 거의 없음 (위치와 길이만)
r: 글자 수정 | 가능 | ❌ 읽기 전용
r: 원래 문자열이 사라지면 | 상관없음 | ❌ 엉뚱한 값 (미정의 동작)
h: 위험 1: 함수 안에서 만든 문자열을 창문으로 돌려주기
code:
#include <iostream>
#include <string>
#include <string_view>

std::string_view makeName()
{
    std::string name { "홍길동" };   // 함수 안에서 만든 문자열
    return name;                     // 문자열이 아니라 "창문"만 돌려줘요
}                                    // ← 여기서 name 이 사라져요

int main()
{
    std::string_view sv { makeName() };   // 이미 사라진 문자열을 보는 창문
    std::cout << sv << '\n';              // ❌ 무엇이 출력될지 몰라요
    return 0;
}
:end
p: `makeName()` 이 끝나는 순간 함수 안의 `name` 은 사라져요. 돌려받은 창문은 빈 자리를 보고 있어서 미정의 동작이에요. 반환형을 `std::string` 으로 바꾸면 문자열 자체가 복사돼 나오니까 안전해요.
term: 댕글링 | dangling | 이미 사라진 대상을 가리키고 있는 상태
h: 위험 2: 창문을 만든 뒤 원래 문자열을 크게 바꾸기
code:
#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string s { "안녕" };
    std::string_view sv { s };          // s 를 보는 창문
    s = "훨씬 더 긴 문자열로 바꿈";        // s 가 더 넓은 메모리로 이사할 수 있어요
    std::cout << sv << '\n';            // ❌ 창문은 옛날 자리를 보고 있어요
    return 0;
}
:end
p: string은 내용이 길어지면 더 넓은 메모리로 옮겨 가요. 창문은 그 사실을 모르고 옛날 위치를 계속 보고 있어서 미정의 동작이 돼요.
h: 언제 무엇을 쓸까요?
tbl: 상황 | 쓸 것
r: 함수가 문자열을 **읽기만** 할 때 (매개변수) | `std::string_view`
r: 함수가 문자열을 **돌려줄** 때 | `std::string`
r: 클래스 안에 문자열을 **저장**할 때 | `std::string`
r: 문자열을 고쳐야 할 때 | `std::string`
star: **잠깐 읽기만 하면 string_view, 가지고 있어야 하면 string.** 헷갈리면 string을 쓰세요(느릴 뿐 틀리지는 않아요).
trap: 함수에서 `std::string_view` 를 반환 > `std::string` 을 반환 > 함수 안 문자열이 사라져서 창문이 빈 자리를 봐요
trap: view를 만든 뒤 원래 string에 긴 문자열을 대입 > view를 다시 만들거나 string을 직접 사용 > 원래 문자열이 이사 가면 view는 옛 자리를 봐요
mem: string_view = **창문**. 집(원본)이 없어지면 아무것도 안 보여요
key: string_view = 복사 없이 보기만, 읽기 전용
key: 매개변수는 string_view, 반환·저장은 string
key: 원래 문자열이 사라지거나 이사 가면 view는 위험해요

# p2-5 | 연산자 우선순위와 계산 순서 | Ch 6.1, 6.4
sum: **우선순위**는 “어떤 것끼리 묶이는지”만 정해요. “어느 쪽을 먼저 계산하는지”는 대부분 정해져 있지 않아요. 그래서 한 식에서 같은 변수를 두 번 바꾸면 안 돼요.
ana: 🧮 우선순위는 식에 괄호를 어디에 칠지 정하는 규칙이에요. 괄호 안의 두 덩어리 중 누가 먼저 계산기를 두드릴지는 컴파일러 마음이에요.
h: 우선순위 — 위에 있을수록 먼저 묶여요
tbl: 순위 | 연산자 | 예
r: 높음 | `++x` `--x` `!` `-x` | `!a`
r:  | `*` `/` `%` | `b * c`
r:  | `+` `-` | `a + b`
r:  | `<<` `>>` | `std::cout << x`
r:  | `<` `<=` `>` `>=` | `x < 5`
r:  | `==` `!=` | `x == 5`
r:  | `&&` | `a && b`
r:  | `\|\|` | `a \|\| b`
r: 낮음 | `?:` `=` `+=` | `x = 5`
p: 다 외울 필요는 없어요. `* / %` 가 `+ -` 보다 먼저라는 것만 알고, 헷갈리면 **괄호**를 치면 돼요.
h: 우선순위와 계산 순서는 달라요
p: `a + b * c` 에서 `b * c` 가 먼저 묶이는 건 우선순위가 정해 줘요. 하지만 `a` 와 `b * c` 중 **어느 쪽 값을 먼저 구할지**는 표준이 정하지 않았어요. 보통은 상관없지만, 계산하면서 변수를 바꾸는 식에서는 문제가 돼요.
code:
#include <iostream>

int main()
{
    int i { 1 };
    std::cout << i++ + ++i << '\n';   // ❌ i 를 두 번 바꿈 → 미정의 동작, 컴파일러마다 결과가 달라요
    return 0;
}
:end
p: `i++` 와 `++i` 중 무엇이 먼저 실행되느냐에 따라 결과가 달라지는데, 그 순서가 정해져 있지 않아서 미정의 동작이에요. 해결은 간단해요. 한 줄에서 한 번만 바꾸도록 **문장을 나누면** 돼요.
star: 한 식 안에서 **같은 변수를 두 번 바꾸지 않아요**. (`i++ + ++i` 는 미정의 동작)
trap: `i++ + ++i` > 문장을 나눠서 하나씩 계산 > 계산 순서가 정해지지 않아 미정의 동작이에요
trap: 우선순위표를 외워서 괄호 없이 긴 식을 씀 > 헷갈리는 곳에 괄호 > 읽는 사람도, 쓰는 나도 실수해요

# p2-6 | 나눗셈, 나머지, 증가 연산자 | Ch 6.2~6.5
sum: 정수끼리 나누면 소수점은 **버려요**. 나머지(`%`)의 부호는 **앞 숫자**를 따라가요. `++x` 는 먼저 올리고, `x++` 는 나중에 올려요.

#include <iostream>

{

    std::cout << -7 % 2 << '\n';    // -1  부호는 앞 숫자(-7)를 따라가요
    return 0;
}
:end
out: 실행 결과

3.5
1
-1
:end
h: 홀수 판정에서 자주 하는 실수
p: 마지막 줄을 보세요. 음수의 나머지는 음수예요. 그래서 “나머지가 1이면 홀수”라고 짜면 음수 홀수(-7)에서 틀려요. “나머지가 0이 아니면 홀수”라고 짜야 해요.
vs: ❌ == 1 로 판정 | ✅ != 0 으로 판정

{
    return x % 2 == 1;
}
// isOdd(-7) → false (틀림)
--

{

}
// isOdd(-7) → true

warn: 거듭제곱 `std::pow(3, 2)` 는 결과를 double로 돌려줘서 8.9999…처럼 오차가 생길 수 있어요. 정수 거듭제곱이 필요하면 반복문으로 곱해요.
h: ++x 와 x++ 의 차이
p: 둘 다 x를 1 올리지만, **식에서 돌려주는 값**이 달라요. 따로 한 줄에 `++x;` 또는 `x++;` 만 쓰면 결과는 같아요. 차이는 다른 식 안에 넣었을 때 생겨요.
code:
#include <iostream>

int main()
{
    int x { 5 };
    int y { ++x };   // 전위: x 를 6 으로 올린 뒤, 6 을 줘요
    std::cout << x << ' ' << y << '\n';

    int a { 5 };
    int b { a++ };   // 후위: 지금 값 5 를 먼저 주고, a 를 6 으로 올려요
    std::cout << a << ' ' << b << '\n';
    return 0;
}
:end

6 5
:end
term: 부작용 | side effect | 값을 계산하는 것 말고 상태를 바꾸는 일 (대입, ++, 출력 등)
star: `7 / 2` 는 3, `-7 % 2` 는 **-1**, `b { a++ }` 에서 b는 **옛 값**이에요.
trap: `sum / count` 로 평균 (둘 다 int) > `static_cast<double>(sum) / count` > 정수끼리 나눠서 소수점이 사라져요
trap: `x % 2 == 1` 로 홀수 판정 > `x % 2 != 0` > 음수 홀수는 나머지가 -1이에요

key: 정수 나눗셈은 소수점 버림, `7 / 2 == 3`
key: 홀수 판정은 `x % 2 != 0`
key: `++x` 는 새 값, `x++` 는 옛 값을 줘요

# p2-7 | 비교 연산자와 논리 연산자 | Ch 6.6~6.8
sum: 실수는 `==` 대신 **차이가 아주 작은지**로 비교해요. `&&` 와 `||` 는 답이 이미 정해지면 **나머지 부분을 계산하지 않아요**(단축 평가).
ana: 🚪 `&&` 는 문 두 개를 모두 통과해야 하는 규칙이에요. 첫 번째 문이 잠겨 있으면 두 번째 문은 열어 보지도 않아요.
h: 실수 비교
p: 1-11에서 봤듯이 `0.1 + 0.2 == 0.3` 은 false예요. 그래서 실수는 “두 값의 차이가 아주 작으면 같다고 보자”는 함수를 만들어 비교해요.
code:
#include <cmath>       // std::abs
#include <iostream>

bool almostEqual(double a, double b)
{
    return std::abs(a - b) < 1e-9;   // 차이가 0.000000001 보다 작으면 같다고 봐요
}

int main()
{
    std::cout << std::boolalpha << almostEqual(0.1 + 0.2, 0.3) << '\n';
    return 0;
}
:end
out: 실행 결과
true
:end
p: `std::abs` 는 절댓값(부호를 뗀 값), `1e-9` 는 10의 −9제곱이에요. 아주 큰 수끼리 비교할 때는 이 고정된 오차가 너무 작을 수 있어서, learncpp 6.7절은 두 수의 크기에 비례하는 오차(상대 오차)를 함께 쓰는 방법을 소개해요.
fix: PPT에 “learncpp **5.7**절 방식”이라고 되어 있지만 실수 비교는 **6.7**절이에요.
h: 단축 평가
p: `A && B` 에서 A가 거짓이면 전체가 거짓으로 정해지니까 B는 계산하지 않아요. `A || B` 에서 A가 참이면 B를 계산하지 않아요. 이 성질 덕분에 “안전 검사를 왼쪽에” 두는 코드가 가능해요.
code:
#include <iostream>

int main()
{
    int* ptr { nullptr };                         // 아무것도 가리키지 않는 포인터 (3회차)
    if (ptr != nullptr && *ptr > 0)               // 왼쪽이 거짓 → 오른쪽(*ptr)은 실행 안 함 ✅
        std::cout << "양수\n";
    else
        std::cout << "검사 통과 못 함\n";
    return 0;
}
:end
out: 실행 결과
검사 통과 못 함
:end
p: 순서를 바꿔 `*ptr > 0 && ptr != nullptr` 로 쓰면, 널 포인터를 먼저 따라가 버려서 프로그램이 멈춰요. **순서 자체가 안전장치**예요.
h: 그 밖에 알아 둘 것
tbl: 규칙 | 내용
r: 드모르간 법칙 | `!(a && b)` 는 `!a \|\| !b` 와 같아요. `!` 를 안으로 넣으면 `&&` 와 `\|\|` 가 뒤바뀌어요
r: 섞어 쓸 때 | `&&` 가 `\|\|` 보다 먼저 묶여요. 헷갈리지 않게 괄호를 쳐요
r: 조건 연산자 `?:` | `x > y ? x : y` — 조건이 참이면 앞, 거짓이면 뒤 값을 줘요
star: 널 검사는 `&&` 의 **왼쪽**에 둬요.
trap: `if (0.1 + 0.2 == 0.3)` > 차이가 아주 작은지로 비교 > 실수는 근삿값이라 ==가 거의 항상 실패해요
trap: `if (a() \|\| b())` 에서 b()가 꼭 실행돼야 함 > b()를 따로 먼저 호출 > a()가 참이면 b()는 건너뛰어요
mem: 드모르간 = `!` 를 안으로 넣으면 `&&` ↔ `||` 가 뒤집혀요
key: 실수는 차이가 아주 작은지로 비교 (6.7절)
key: `&&` 는 왼쪽이 거짓, `||` 는 왼쪽이 참이면 오른쪽을 안 봐요
key: 안전 검사는 왼쪽에

# p2-8 | 스코프, 수명, 링키지 | Ch 7.1~7.8, 7.12
sum: 변수에는 세 가지 성질이 있어요. **어디서 보이나**(스코프), **언제까지 살아 있나**(수명), **다른 파일에서도 같은 변수인가**(링키지).
ana: 🏢 회사 출입증에 비유하면, 스코프는 출입증이 통하는 층, 수명은 근무 기간, 링키지는 다른 지점에서도 같은 사람으로 통하는지예요.
h: 세 성질 한눈에
tbl: 성질 | 묻는 것 | 종류
r: 스코프 (scope) | 이 이름을 **어디서** 쓸 수 있나요 | 블록(중괄호 안) / 전역(파일 전체)
r: 수명 (duration) | 이 변수가 **언제** 생기고 사라지나요 | 자동(블록 끝에서 사라짐) / 정적(프로그램 끝까지)
r: 링키지 (linkage) | 다른 **파일**의 같은 이름이 같은 변수인가요 | 없음 / 내부(이 파일만) / 외부(다른 파일도)
h: 스코프: 안쪽 이름이 바깥 이름을 가려요
p: 중괄호 `{ }` 안에서 만든 변수는 그 중괄호가 끝나면 사라져요. 안쪽에서 바깥과 같은 이름을 쓰면 안쪽 것이 바깥 것을 **가려요**(섀도잉).
code:
#include <iostream>

int value { 10 };                      // 전역 변수

int main()
{
    int value { 20 };                  // 전역 value 를 가려요
    {
        int value { 30 };              // 또 가려요
        std::cout << value << '\n';    // 30 — 가장 안쪽
    }                                  // 여기서 30짜리 value 는 사라져요
    std::cout << value << '\n';        // 20
    std::cout << ::value << '\n';      // 10 — :: 를 붙이면 전역
    return 0;
}
:end
out: 실행 결과
30
20
10
:end
tip: 변수는 필요한 곳에서 **최대한 좁은 범위**에 만들어요. 신경 쓸 변수가 줄고 이름 충돌도 줄어요.
h: 링키지: 다른 파일에서 쓸 수 있나요?
code:
// ── a.cpp ──
int g_count { 0 };            // 외부 링키지 — 다른 파일에서도 쓸 수 있어요
static int s_helper { 0 };    // 내부 링키지 — 이 파일 안에서만
const int g_max { 100 };      // const 전역은 기본이 내부 링키지

// ── b.cpp ──
extern int g_count;           // "a.cpp에 있는 그 g_count 를 쓸게요" (선언만, 값 없음)
void increase() { ++g_count; }
:end
tbl: 선언 | 다른 파일에서 쓸 수 있나요
r: `int g_count { 0 };` (함수 밖) | ✅ `extern int g_count;` 로 가져와서
r: `static int s { 0 };` (함수 밖) | ❌ 이 파일만
r: `const int g { 100 };` (함수 밖) | ❌ 기본이 이 파일만
warn: 값을 바꿀 수 있는 전역 변수는 되도록 피해요. 어느 함수가 언제 바꿨는지 추적하기 어렵고, 테스트도 어려워져요.
star: 위 코드의 출력 순서 **30 → 20 → 10**. `::value` 는 전역 변수예요.
trap: 다른 파일에서 `static` 전역 변수를 `extern` 으로 가져옴 > static을 빼서 외부 링키지로 > static 전역은 그 파일 안에서만 보여서 링크 오류가 나요
mem: **스**코프 = **시**야(보이는 곳), **수**명 = **살**아 있는 기간, **링**키지 = 파일끼리 **연결**
key: 스코프(어디서) · 수명(언제까지) · 링키지(다른 파일)
key: 안쪽 이름이 바깥을 가림, `::이름` 은 전역
key: static·const 전역은 이 파일만, extern 은 “다른 파일 것을 쓸게”

# p2-9 | 헤더 상수, static 지역 변수, using | Ch 7.9~7.14
sum: 여러 파일이 같이 쓰는 상수는 헤더에 **`inline constexpr`** 로 둬요. 함수 안의 **static 변수**는 함수가 끝나도 값이 남아요. using은 필요한 이름만 좁게 써요.
ana: 📌 함수 안 static 변수는 회의실 화이트보드예요. 회의(함수)가 끝나도 지워지지 않아서, 다음 회의 때 이어서 쓸 수 있어요.
h: 헤더에 상수 두기
p: 상수를 헤더에 `constexpr` 로만 두면, 그 헤더를 include하는 파일마다 상수 사본이 하나씩 생겨요. `inline` 을 붙이면 프로그램 전체에 **하나만** 생겨요.
code:
// ── constants.h ──
#pragma once
namespace constants
{
    inline constexpr double gravity { 9.8 };   // 프로그램 전체에 하나
    inline constexpr int maxUsers { 100 };
}

// ── main.cpp ──
#include <iostream>
#include "constants.h"
int main() { std::cout << constants::gravity << '\n'; }
:end
term: inline (변수) | inline variable | “같은 정의가 여러 파일에 있어도 하나로 취급해 줘”라는 표시 (C++17)
h: 함수 안의 static 변수
p: 보통 함수 안의 변수는 함수가 끝나면 사라지고, 다음에 부르면 처음부터 다시 만들어져요. `static` 을 붙이면 **처음 한 번만** 만들어지고, 함수가 끝나도 값이 그대로 남아요.
code:
#include <iostream>

void counter()
{
    static int calls { 0 };   // 처음 불릴 때 딱 한 번만 0 으로 만들어져요
    ++calls;
    std::cout << calls << '\n';
}

int main()
{
    counter();
    counter();
    counter();
    return 0;
}
:end
out: 실행 결과
1
2
3
:end
p: static을 빼면 매번 0에서 시작해서 1, 1, 1이 나와요. 이름은 여전히 함수 안에서만 보이고(스코프 그대로), **사는 기간만** 프로그램 끝까지로 늘어난 거예요.
h: static은 위치에 따라 뜻이 달라요
tbl: 어디에 쓰나요 | 뜻
r: **함수 안** `static int x;` | 수명을 프로그램 끝까지로 (값이 유지돼요)
r: **함수 밖** `static int x;` | 이 파일에서만 보이게 (내부 링키지)
h: 스코프·수명·링키지 정리표
tbl: 선언 | 스코프 | 수명 | 링키지
r: 함수 안 `int x;` | 블록 | 자동 | 없음
r: 함수 안 `static int x;` | 블록 | 정적 | 없음
r: 함수 밖 `int x;` | 전역 | 정적 | 외부
r: 함수 밖 `static int x;` | 전역 | 정적 | 내부
r: 함수 밖 `const int x { 1 };` | 전역 | 정적 | 내부
r: `inline constexpr int x { 1 };` | 전역 | 정적 | 외부 (하나만)
h: using 은 좁게
tbl: 쓰는 법 | 괜찮을까요?
r: `using namespace std;` | ❌ std의 모든 이름이 쏟아져 나와 충돌 위험
r: 함수 안 `using std::cout;` | ✅ 필요한 이름 하나만, 그 함수 안에서만
star: `static` 은 **함수 안에서는 수명**, **함수 밖에서는 링키지**를 바꿔요.
trap: 헤더에 `constexpr double g { 9.8 };` > `inline constexpr double g { 9.8 };` > include하는 파일마다 사본이 생겨요
trap: 호출 횟수를 세려고 함수 안에 그냥 `int calls { 0 };` > `static int calls { 0 };` > 매번 0부터 다시 시작해요
mem: static — 함수 안에서는 **오래 살기**, 함수 밖에서는 **집 밖에 못 나가기**
key: 헤더 상수는 `inline constexpr`
key: 함수 안 static = 한 번만 만들어지고 값이 유지돼요
key: static은 위치에 따라 뜻이 달라요

# p2-10 | if 와 switch | Ch 8.2~8.6
sum: if는 한 줄짜리여도 **항상 중괄호**를 쳐요. switch는 case 끝에 **break** 가 없으면 아래 case까지 계속 실행돼요.
ana: 🌊 switch의 case는 계단식 물웅덩이예요. break라는 둑이 없으면 물이 아래 칸으로 계속 흘러내려요.
h: if에서 자주 하는 실수 4가지

if (x > 5);              // ① 괄호 뒤 ; — if 가 여기서 끝나요

if (x = 5)               // ② = 는 대입이에요. x 가 5 가 되고, 조건은 항상 참

if (x > 5)
    std::cout << "큼";
    std::cout << "확실";  // ④ 들여쓰기만 했을 뿐 if 밖이에요. 항상 실행돼요

# p2-11 | 반복문, 프로그램 끝내기, 난수 | Ch 8.7~8.15
sum: 몇 번 돌지 모르면 **while**, 최소 한 번은 돌아야 하면 **do-while**, 횟수가 정해져 있으면 **for**. 난수는 `rand()` 대신 **`<random>`** 의 엔진과 분포를 써요.
ana: 🏃 while은 “지칠 때까지 뛰어”, do-while은 “일단 한 바퀴 뛰고 나서 판단해”, for는 “운동장 5바퀴”예요.
h: 반복문 세 가지
tbl: 형태 | 언제 쓰나요
r: `while (조건) { }` | 몇 번 돌지 모를 때. 처음부터 조건이 거짓이면 한 번도 안 돌아요
r: `do { } while (조건);` | 최소 한 번은 실행해야 할 때 (메뉴 보여 주기, 다시 입력받기)
r: `for (시작; 조건; 증가) { }` | 횟수가 정해져 있을 때
code:
#include <iostream>

int main()
{
    for (int i { 0 }; i < 5; ++i)    // i 가 0,1,2,3,4 일 때 → 5번
        std::cout << i << ' ';
    std::cout << '\n';

    int n { 0 };
    while (true)                     // 무한 반복 + 안에서 빠져나가기
    {
        ++n;
        if (n % 2 == 0) continue;    // 짝수면 이번 회차만 건너뛰기
        if (n > 7) break;            // 7보다 커지면 반복 전체를 끝내기
        std::cout << n << ' ';
    }
    return 0;
}
:end
out: 실행 결과
0 1 2 3 4
1 3 5 7
:end
tbl: 키워드 | 하는 일
r: `break` | 반복문을 **완전히** 빠져나가요
r: `continue` | 이번 회차의 나머지를 건너뛰고 **다음 회차**로 가요
warn: `for (int i { 0 }; i <= 5; ++i)` 는 0부터 5까지 **6번** 돌아요. 5번을 원했다면 `<` 를 써야 해요.
h: 프로그램을 중간에 끝내는 방법
tbl: 방법 | 뒷정리
r: main에서 `return` | ✅ 모든 변수가 정상적으로 정리돼요 — 가장 안전
r: `std::exit(코드)` | 지금 실행 중인 함수의 지역 변수는 정리되지 않아요
r: `std::abort()` | 아무것도 정리하지 않고 즉시 멈춰요
h: 난수: 1~6 주사위 만들기
p: 난수는 **부품 두 개**로 만들어요. 숫자를 마구 쏟아내는 **엔진**과, 그 숫자를 원하는 범위(1~6)로 고르게 바꿔 주는 **분포**예요. 엔진은 처음 시작점(시드)이 필요한데, 그걸 정해 주는 장치가 `std::random_device` 예요.
code:
#include <iostream>
#include <random>

int main()
{
    std::random_device rd;                        // ① 시작점(시드)을 정해 주는 장치
    std::mt19937 gen { rd() };                    // ② 엔진: rd에게서 시작점을 받아 숫자를 만들기 시작
    std::uniform_int_distribution die { 1, 6 };   // ③ 분포: 숫자를 1~6 사이로 고르게 바꿔 줌

    for (int i { 0 }; i < 5; ++i)
        std::cout << die(gen) << ' ';             // ④ 엔진에서 숫자 하나를 뽑아 1~6으로 바꿔 출력
    std::cout << '\n';
    return 0;
}
:end
out: 실행 결과 (매번 달라요)
3 6 1 1 4
:end
tbl: 이름 | 뜻
r: `std::random_device` | 엔진의 시작점을 정해 주는 장치. 실행할 때마다 다른 시작점을 줘요
r: `std::mt19937` | 엔진 종류의 이름이에요. “표준 엔진”이라고만 알면 돼요
r: `std::uniform_int_distribution` | uniform(고르게) + int(정수) + distribution(분포) → “정수를 고르게”
r: `die(gen)` | 분포 die에게 엔진 gen을 넘겨서 “하나 뽑아 줘”
p: PPT에 나온 `std::mt19937 gen{ std::random_device{}() };` 는 위의 ①②를 한 줄로 줄인 거예요. `std::random_device{}` 로 장치를 잠깐 만들고, 바로 `()` 로 숫자 하나를 뽑아 엔진에 넣어요.
h: rand() 를 쓰지 않는 이유
tbl: `std::rand() % 6 + 1` 의 문제 | `<random>` 은
r: 만들어 내는 숫자의 품질이 낮아요 | 품질 좋은 엔진을 골라 써요
r: `%` 로 자르면 특정 숫자가 조금 더 자주 나와요 | 분포가 고르게 맞춰 줘요
warn: 엔진은 **한 번만** 만들어서 계속 써요. 함수를 부를 때마다 엔진을 새로 만들면 비슷한 시작점에서 다시 시작해서 같은 숫자가 반복될 수 있어요.
tip: 디버깅할 때는 `std::mt19937 gen { 42 };` 처럼 시작점을 고정하면 매번 같은 숫자가 나와서 버그를 재현하기 좋아요.
star: `i <= 5` 로 0부터 세면 **6번** 돌아요. 난수는 **엔진(mt19937) + 분포(uniform_int_distribution)**.
trap: `for (int i { 0 }; i <= 5; ++i)` 로 5번 > `i < 5` > 0부터 5까지 6번 돌아요
trap: 난수 함수 안에서 엔진을 매번 새로 만듦 > 엔진은 한 번만 만들어 재사용 > 같은 숫자가 반복될 수 있어요
mem: **break** = 반복을 부수고 나가기, **continue** = 이번 판만 넘기고 계속
key: while(몰라요) · do-while(최소 1번) · for(정해져 있어요)
key: `<=` 는 한 번 더 돌아요 (off-by-one)
key: 난수 = 엔진 + 분포, 엔진은 한 번만 만들기

# p2-12 | 테스트와 오류 다루기 | Ch 9.1~9.4

# p2-13 | 잘못된 입력 처리와 assert | Ch 9.5~9.6
sum: 숫자를 받아야 하는데 글자가 들어오면 cin이 고장 난 상태가 돼요. **`clear()` 로 고장 표시를 지우고 → `ignore()` 로 남은 글자를 버리면** 다시 입력받을 수 있어요.
ana: 🚩 cin은 잘못된 입력을 만나면 빨간 깃발을 들고 일을 멈춰요. clear로 깃발을 내리고, ignore로 바닥에 남은 쓰레기를 치워야 다시 일해요.
h: 먼저 문제 상황
p: `int x; std::cin >> x;` 에 “abc”를 입력하면 x에는 아무것도 안 들어가고 cin은 **실패 상태**가 돼요. 이 상태에서는 이후의 모든 입력을 무시해요. 게다가 “abc”는 읽히지 않고 그대로 남아 있어요.
h: 해결 코드 (과제에 자주 나와요)
code:
#include <iostream>
#include <limits>     // std::numeric_limits

int main()
{
    int x {};
    while (true)
    {
        std::cout << "정수: ";
        std::cin >> x;
        if (!std::cin)                     // 입력이 실패했다면
        {
            std::cin.clear();              // ① 실패 상태(빨간 깃발)를 지워요
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');   // ② 그 줄에 남은 글자를 전부 버려요
            std::cout << "숫자가 아니에요\n";
            continue;                      // 다시 입력받기
        }
        break;                             // 제대로 들어왔으면 반복 끝
    }
    std::cout << "입력한 수: " << x << '\n';
    return 0;
}
:end
out: 입력: abc ⏎ 42
정수: 숫자가 아니에요
정수: 입력한 수: 42
:end
tbl: 코드 조각 | 뜻
r: `!std::cin` | “cin이 실패 상태인가?”
r: `std::cin.clear()` | 실패 상태를 지워서 다시 입력받을 수 있게 해요
r: `std::cin.ignore(최대 개수, '\n')` | 줄바꿈('\n')이 나올 때까지 남은 글자를 버려요
r: `std::numeric_limits<std::streamsize>::max()` | “버릴 수 있는 최대 개수” — 사실상 “줄 끝까지 전부”
tbl: 빼먹으면 | 생기는 일
r: `clear()` 를 빼먹음 | cin이 계속 실패 상태라 모든 입력이 무시돼요 → **무한 반복**
r: `ignore()` 를 빼먹음 | 남은 “abc”를 다시 읽고 또 실패해요 → **무한 반복**
r: 순서를 바꿈 (ignore 먼저) | 실패 상태에서는 ignore도 동작하지 않아요 → **무한 반복**
h: assert 와 static_assert
p: assert는 “여기서는 절대 이런 일이 없어야 한다”를 확인하는 장치예요. 실행 중에 검사하고, 조건이 거짓이면 즉시 멈춰요. static_assert는 같은 일을 **컴파일할 때** 해요.
code:
#include <cassert>
#include <iostream>

double divide(int a, int b)
{
    assert(b != 0 && "0으로 나눌 수 없어요");   // b가 0이면 여기서 멈추고 이 메시지를 보여 줘요
    return static_cast<double>(a) / b;
}

static_assert(sizeof(int) >= 4, "int가 4바이트 이상이라고 가정한 코드예요");   // 컴파일할 때 검사

int main()
{
    std::cout << divide(7, 2) << '\n';
    return 0;
}
:end
out: 실행 결과
3.5
:end
tbl:  | assert | static_assert
r: 언제 검사하나요 | 실행 중 | 컴파일할 때
r: 실패하면 | 프로그램이 즉시 멈춰요 | 컴파일 오류
r: Release 빌드 (`NDEBUG`) | **사라져요** (검사 안 함) | 그대로 검사해요
warn: assert 괄호 안에서 값을 바꾸면 안 돼요. `assert(++i < 10);` 은 Release 빌드에서 줄 전체가 사라지니까 `++i` 도 같이 사라져요.
star: 입력 실패 처리는 **clear → ignore** 순서예요.
trap: 입력 실패 후 `continue` 만 함 > `clear()` 와 `ignore()` 를 먼저 > 실패 상태가 남아 무한 반복이에요
trap: `assert(++i < 10);` > `++i;` 를 따로 쓰고 `assert(i < 10);` > Release에서 assert가 사라지며 ++i도 사라져요
trap: 사용자 입력이 맞는지 assert로 검사 > 일반 if로 검사하고 다시 입력받기 > assert는 Release에서 사라지는 개발용 확인 장치예요
mem: **깃발 내리고(clear) → 쓰레기 치우기(ignore)**
key: 입력 실패 → `clear()` 후 `ignore(max, '\n')`
key: assert는 실행 중 검사, Release에서 사라져요
key: static_assert는 컴파일할 때 검사
