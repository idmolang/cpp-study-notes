# p1-1 | 코드가 프로그램이 되기까지 | Ch 0.5
sum: 내가 쓴 .cpp 파일은 **전처리 → 컴파일 → 링크** 3단계를 거쳐 실행 파일이 된다.
ana: 🍳 요리로 치면 — 재료 손질(전처리) → 요리마다 따로 조리(컴파일) → 한 상에 차리기(링크).
h: 3단계 한눈에
flow: ① 전처리 > `#include` 내용을 그 자리에 복사·붙여넣기 || ② 컴파일 > .cpp 를 **하나씩** 기계어로 번역 → .o 파일 || ③ 링크 > .o 조각들을 이어 붙여 → 실행 파일
h: 오류도 단계마다 다르게 생겼다
tbl:  | 컴파일 오류 | 링크 오류
r: 언제 | 파일 하나 번역하다가 | 조각을 이어 붙이다가
r: 원인 | 문법 틀림, 모르는 이름 | 함수 “선언”만 있고 “몸통(정의)”이 없음
r: 생김새 | 파일명 + **줄 번호** | 줄 번호 없이 `undefined reference`
h: 컴파일러는 파일을 하나씩만 본다
li: .cpp 하나(+ 그 안의 #include) = **번역 단위**
li: 컴파일러는 지금 번역 중인 파일 말고 **다른 .cpp 는 전혀 모름**
li: 그래서 다른 파일의 함수를 쓰려면 “이런 함수 있어요”라고 미리 알려야 함 → 1-7 전방 선언
code:
g++ -c main.cpp          # 번역만 → main.o
g++ -c add.cpp           # 번역만 → add.o
g++ main.o add.o -o app  # 이어 붙이기(링크) → app
:end
star: 오류에 **줄 번호가 있으면 컴파일 오류**, 줄 번호 없이 **`undefined reference` 면 링크 오류**.
trap: `g++ main.cpp` 만 빌드 (add.cpp 빠뜨림) > `g++ main.cpp add.cpp` > add 의 몸통을 못 찾아 링크 오류
mem: `-c` = **c**ompile only → 이어 붙이기 직전에서 멈춤
key: 빌드 = 전처리 → 컴파일 → 링크
key: 줄 번호 있으면 컴파일 오류, `undefined reference` 면 링크 오류
key: 컴파일러는 .cpp 를 하나씩, 따로 본다

# p1-2 | Debug vs Release, 그리고 첫 프로그램 | Ch 0.7~0.9
sum: 개발할 땐 **Debug**(느리지만 추적 쉬움), 내보낼 땐 **Release**(빠름). main 이 돌려주는 0 은 “성공”.
ana: 🚗 Debug = 연습용 교습 차(천천히, 브레이크 2개), Release = 실전 경주용 차(빠르지만 안을 들여다보기 어려움).
h: 둘의 차이
tbl:  | Debug | Release
r: 최적화 | 끔 | 켬
r: 속도 | 느림 | 빠름
r: 디버거로 한 줄씩 보기 | 잘 됨 | 흐름이 뒤섞여 어려움
r: 언제 | 개발·버그 잡기 | 배포·속도 재기
warn: Debug 에선 되는데 Release 에서만 깨진다? → 컴파일러 탓 아님. 내 코드에 **미정의 동작(UB)** 이 숨어 있는 것 (초기화 안 한 변수 등).
h: 첫 프로그램
code:
#include <iostream>

int main()
{
    std::cout << "Hello, world!\n";
    return 0;   // 0 = 성공했다고 운영체제에 알림
}
:end
tbl: 이런 오류가 나면 | 원인
r: `iostream: No such file` | 표준 헤더는 `< >`, 내 파일은 `" "`
r: `undefined reference to main` | main 이 없거나 철자 틀림 (Main, mian)
star: main 의 반환값 = **종료 코드**. **0 = 성공**, 0 이 아니면 실패.
trap: Debug 빌드로 속도를 잼 > Release 로 잰다 > Debug 속도는 실제 성능과 무관
mem: **D**ebug = **D**etective(탐정, 느리게 조사), **R**elease = **R**ace(경주)
key: 개발은 Debug, 배포·속도 측정은 Release
key: Release 에서만 깨지면 UB 를 의심
key: `return 0;` = 성공

# p1-3 | 프로그램 구조와 변수 | Ch 1.1~1.3
sum: 프로그램은 **문장**이 모인 **함수**들이고, 시작은 언제나 **main**. 변수는 이름 붙은 메모리 칸.
ana: 📦 변수 = 이름표 붙인 상자. 상자(객체)는 메모리 칸이고, 이름표가 변수 이름.
h: 구성 요소 4가지
dl: 문장 > 일 하나. 대부분 `;` 으로 끝남
dl: 함수 > 문장들을 묶어 이름 붙인 것
dl: main > 프로그램 시작점. **딱 하나**, 반환형은 **int**
dl: `#` 지시문 > 컴파일 전에 처리됨. **`;` 없음**
code:
#include <iostream>        // # 지시문 — 세미콜론 없음

int main()                 // 시작점
{
    int x { 5 };           // 문장
    std::cout << x;        // 문장
    return 0;              // 문장
}
:end
h: 객체와 변수
tbl: 말 | 뜻
r: 객체 (object) | 값을 담으려고 잡은 **메모리 칸**
r: 변수 (variable) | **이름이 붙은** 객체
star: C++ 에서 “객체”는 클래스와 상관없는 말. **`int x;` 도 객체**다.
h: 이렇게 쓰자
li: 변수는 **쓰기 직전에** 만든다 (맨 위에 몰아 두지 않기)
li: **한 줄에 하나씩** 선언
li: 주석엔 “무엇을”보다 **“왜”** 를 쓴다
trap: `int a, double b;` > 줄을 나눠 따로 선언 > 타입이 다른 변수는 한 문장에 못 씀
mem: 상자(객체) + 이름표(변수 이름) = 변수
key: 시작은 main (하나, 반환형 int)
key: 객체 = 메모리 칸, 변수 = 이름 붙은 객체
key: 변수는 쓰기 직전에, 한 줄에 하나씩

# p1-4 | 초기화는 { } 로, 안 하면 위험 | Ch 1.4, 1.6
sum: 변수는 만들자마자 **`{ }` 로 값을 넣는다**. 안 넣고 읽으면 **미정의 동작(UB)**.
ana: 🏠 새 집에 이사 왔는데 청소 안 하면 전 주인 짐(쓰레기 값)이 그대로 있음. `{ }` = 입주 청소.
h: 초기화 5가지 — 하나만 기억
tbl: 코드 | 결과
r: `int a;` | ❌ 값이 뭔지 모름 (위험)
r: `int b = 5;` | 5 — 옛날 방식
r: `int c ( 5 );` | 5 — 함수랑 헷갈림
r: `int d { 5 };` | ✅ **5 — 이걸 쓴다**
r: `int e {};` | ✅ **0**
h: 왜 { } 인가?
vs: = 로 넣으면 | { } 로 넣으면
int n = 4.9;
// n 은 4
// 0.9 가 조용히 사라짐
--
int n { 4.9 };
// 컴파일 오류!
// 실수를 바로 알려 줌
:end
star: `{ }` 는 값이 잘려 나가는 **축소 변환**을 **컴파일 오류**로 막아 준다.
h: 미정의 동작 (UB) 이란?
li: 표준이 “**무슨 일이 생길지 책임 안 짐**”이라고 한 상황
li: 매번 다른 값, 크래시, 아무 일 없음… 전부 가능
li: “**항상 0 이 나와서**” 괜찮아 보이는 게 제일 위험 (버그가 숨음)
tbl: 자주 만나는 UB 5가지
r: ① 초기화 안 한 변수 읽기
r: ② int 범위 넘기기 (오버플로)
r: ③ 반환형 있는 함수에서 return 빠뜨리기
r: ④ 널·사라진 객체 건드리기
r: ⑤ 배열 범위 밖 접근
trap: `int x; std::cout << x;` > `int x {};` > 쓰레기 값 읽기 = UB
mem: `{ }` = **울타리**. 값이 줄어들면(4.9 → 4) 못 넘어감
key: 초기화는 `int x { 5 };`, 값이 없으면 `int x {};` (= 0)
key: `{ }` 는 축소 변환을 컴파일 오류로 잡음
key: 초기화 안 한 변수 읽기 = UB

# p1-5 | 입출력 · 이름 짓기 · 표현식 | Ch 1.5, 1.7~1.10
sum: `<<` 로 내보내고 `>>` 로 받는다. 줄바꿈은 `'\n'`. **표현식은 값**을 만들고, **문장은 일**을 한다.
ana: ➡️ 화살표 방향 = 데이터가 흐르는 방향. `cout << x` 는 x 가 화면으로, `cin >> x` 는 키보드 입력이 x 로.
h: 입출력
code:
std::string name {};
int age {};
std::cin >> name >> age;                  // 공백 기준으로 하나씩 읽음
std::cout << name << ' ' << age << '\n';  // 이어서 출력 가능
:end
tbl: 줄바꿈 | 차이
r: `'\n'` | ✅ 줄만 바꿈 — 빠름
r: `std::endl` | 줄 바꾸고 **버퍼까지 비움** — 반복문에서 느림
h: 이름 짓기 규칙
tbl: 꼭 지킬 것 | 지키면 좋은 것
r: 문자·숫자·`_` 만 | 소문자로 시작: `itemCount`
r: 숫자로 시작 ❌ | `_` 로 시작 ❌ (예약됨)
r: 키워드 ❌, 대소문자 구분 | 쓰는 범위가 넓을수록 길게
h: 표현식 vs 문장
tbl: 말 | 뜻 | 예
r: 리터럴 | 코드에 박힌 고정값 | `5` `3.14` `'a'` `"hi"` `true`
r: 표현식 | **값 하나**를 만드는 조각 | `2 + 3` → 5
r: 문장 | 표현식 + `;` → 일을 시킴 | `x = 4;`
star: `'\n'` 이 기본, `std::endl` 은 flush 까지 해서 느림.
trap: 반복문 안에서 `std::endl` > `'\n'` > 매번 버퍼를 비워서 느려짐
mem: 표현식 = **값**, 문장 = **일**
key: 출력 `<<`, 입력 `>>`, 줄바꿈 `'\n'`
key: 이름: 문자·숫자·_ , 숫자로 시작 X
key: 표현식은 값, `;` 붙이면 문장

# p1-6 | 함수: 매개변수 · 인자 · 반환 | Ch 2.1~2.4
sum: 함수 정의 쪽 변수 = **매개변수**, 부를 때 넣는 값 = **인자**. 넘길 땐 **복사**된다. return 을 빠뜨리면 UB.
ana: 🧾 매개변수 = 주문서의 빈칸, 인자 = 손님이 빈칸에 적어 낸 값. 주방엔 **복사본**이 감.
h: 함수 생김새
code:
int add(int a, int b)   // a, b = 매개변수 (빈칸)
{
    return a + b;       // 값을 돌려주고 즉시 끝
}

int sum { add(3, 4) };  // 3, 4 = 인자 (채운 값)
:end
tbl: 말 | 어디에 | 예
r: 매개변수 (parameter) | 함수 **정의** 쪽 | `int a`
r: 인자 (argument) | 함수 **호출** 쪽 | `3`
r: 값 전달 | 인자가 **복사**됨 | 안에서 바꿔도 원본 그대로
h: return 규칙
vs: ❌ return 빠짐 | ✅ 모든 길에 return
int get(bool f)
{
    if (f) return 1;
    // f 가 false 면? → UB
}
--
int get(bool f)
{
    if (f) return 1;
    return 0;
}
:end
tbl: 상황 | 결과
r: 반환형 있는데 return 없는 길 | ❌ UB
r: **main** 만 return 생략 | ✅ 자동으로 `return 0;`
r: 반환값을 안 씀 `add(3,4);` | ✅ 괜찮음
r: void 함수 값을 쓰려 함 | ❌ 컴파일 오류
star: return 생략이 허락되는 건 **main 하나뿐**.
trap: 어떤 if 갈래에서 return 을 빠뜨림 > 마지막 줄에 기본 return > 반환값을 쓰는 순간 UB
mem: **파**라미터 = 정의 **파**일 쪽 빈칸, **인**자 = 실제로 **넣**는 값
key: 매개변수(정의) ↔ 인자(호출), 넘기면 복사
key: 반환형 있으면 모든 길에 return (main 만 예외)
key: 함수 하나엔 일 하나

# p1-7 | 선언 · 정의 · 헤더 파일 | Ch 2.7~2.12
sum: **선언** = “이런 게 있다”(여러 번 OK), **정의** = 실제 몸통(**딱 한 번**). 헤더엔 선언, .cpp 엔 정의.
ana: 📇 선언 = 명함(“저 여기 있어요”), 정의 = 실제 사람. 명함은 여러 장 뿌려도 되지만 사람은 한 명.
h: 왜 선언이 필요해?
li: 컴파일러는 위에서 아래로 **한 번만** 읽음
li: 아직 안 나온 함수를 부르면 “그게 뭔데?” → 오류
li: 해결: 맨 위에 **전방 선언** 한 줄
code:
int add(int a, int b);        // 전방 선언 (몸통 없음, ; 로 끝)

int main() { std::cout << add(3, 4); }

int add(int a, int b)         // 정의 (몸통)
{
    return a + b;
}
:end
h: 선언 vs 정의
tbl:  | 선언 | 정의
r: 뜻 | “이런 이름이 있다” | 실제 내용
r: 몇 번? | 여러 번 OK | **프로그램 전체에서 딱 1번** (ODR)
r: 빠뜨리면 | 컴파일 오류 | **링크 오류**
h: 파일 나누기
tbl: 파일 | 넣을 것
r: `add.h` | 선언만 + 헤더 가드
r: `add.cpp` | 정의(몸통)
r: `main.cpp` | `#include "add.h"` 후 사용
code:
// add.h
#ifndef ADD_H        // 헤더 가드: 두 번 포함 방지
#define ADD_H
int add(int a, int b);
#endif
:end
star: 선언만 있고 정의가 없으면 → **컴파일은 통과, 링크에서 `undefined reference`**.
trap: 헤더에 함수 **몸통**까지 씀 > 헤더엔 선언만 > 여러 파일에 복사돼 정의가 여러 개 → 링크 오류
mem: 명함(선언)은 여러 장, 사람(정의)은 한 명 = **ODR**
key: 선언 여러 번, 정의 한 번 (ODR)
key: 헤더 = 선언, .cpp = 정의
key: 정의 빠짐 = 링크 오류

# p1-8 | 네임스페이스와 전처리기 | Ch 2.9~2.10
sum: 이름이 겹치면 **네임스페이스**로 구분 (`math::add`). `using namespace std;` 는 쓰지 말 것. 전처리기는 문법 모르는 **텍스트 치환기**.
ana: 🏫 네임스페이스 = 반 이름. “1반 철수”, “2반 철수”라고 부르면 안 헷갈림. `::` 가 “~반의”.
h: 네임스페이스
code:
namespace math    { int add(int a, int b) { return a + b; } }
namespace physics { int add(int a, int b) { return a + b; } }

math::add(3, 4);      // :: = "~안의"
physics::add(3, 4);   // 이름이 같아도 OK
:end
tbl: 방법 | 괜찮나?
r: `using namespace std;` | ❌ std 전체를 끌어와 `count`, `data` 등과 충돌
r: 헤더에 `using namespace` | ❌❌ 포함한 **모든 파일** 오염
r: 함수 안에서 `using std::cout;` | ✅ 필요한 것만, 좁게
h: 전처리기가 하는 3가지
flow: `#include` > 파일 내용을 통째로 붙여넣기 || `#define` > 글자를 다른 글자로 바꿔치기 || `#ifdef` > 조건 안 맞는 코드는 지워 버림
li: 전처리기는 C++ 문법을 **모름** — 그냥 글자 바꾸기
li: 매크로는 정의된 곳부터 **그 파일 끝까지**만
li: 상수는 매크로 대신 `constexpr` (2회차)
star: `using namespace std;` 는 쓰지 않는다 — 특히 **헤더에는 절대**.
trap: 헤더에 `using namespace std;` > 함수 안에서 `using std::cout;` > 그 헤더를 쓰는 모든 파일에 이름 충돌이 퍼짐
mem: `::` = “~반의” (math 반의 add)
key: 이름 충돌은 `namespace::이름` 으로
key: `using namespace std;` 금지
key: 전처리기 = 문법 모르는 글자 치환

# p1-9 | 디버깅 | Ch 3.1~3.10
sum: 문법 오류는 컴파일러가 잡지만, **의도와 다르게 도는 오류**는 내가 찾아야 한다. 추측 말고 **좁혀 가며** 찾기.
ana: 🔦 디버깅 = 정전된 집에서 차단기 찾기. 아무거나 누르지 말고, 절반씩 꺼 보며 범위를 좁힘.
h: 오류 2종류
tbl:  | 구문 오류 | 의미 오류
r: 뜻 | 문법이 틀림 (`;` 빠짐) | 문법은 맞는데 **결과가 틀림**
r: 누가 찾나 | 컴파일러가 줄까지 알려 줌 | **내가** 찾아야 함
r: 난이도 | 쉬움 | 어려움
code:
for (int i { 0 }; i <= 5; ++i)   // 5번 돌리려 했는데 6번 돎 (의미 오류)
    std::cout << i;
:end
h: 찾는 순서 5단계
flow: 1 재현 > 매번 똑같이 버그가 나게 || 2 범위 좁히기 > 절반씩 확인 || 3 원인 확인 > 그 지점 값이 예상과 다른가 || 4 고치기 > 증상 말고 **원인**을 || 5 다시 확인 > 다른 데 안 깨졌나
h: 디버거 버튼 3개
tbl: 버튼 | 하는 일
r: Step **into** | 함수 **안으로** 들어감
r: Step **over** | 함수를 **통째로** 실행하고 다음 줄
r: Step **out** | 지금 함수를 끝내고 **밖으로**
r: 중단점 | 그 줄에서 멈춤
r: 호출 스택 | “여기까지 어떻게 왔지?” 경로
star: 오류는 **첫 번째 것부터** 고친다. 하나가 수십 개를 만든다.
trap: 결과가 1 크니까 `-1` 을 붙임 > 왜 1 큰지 원인을 찾음 > 증상만 가리면 다른 곳에서 또 터짐
trap: Release 빌드로 디버깅 > Debug 빌드로 > 최적화로 흐름이 뒤섞여 변수가 안 보임
mem: into = 안으로 쏙, over = 건너뛰기, out = 밖으로 탈출
key: 구문 오류는 컴파일러가, 의미 오류는 내가
key: 첫 오류부터, 절반씩 좁히기
key: Step into / over / out

# p1-10 | 정수: 크기 · 오버플로 · unsigned | Ch 4.1~4.5
sum: 정수는 **int** 가 기본. 범위를 넘으면 int 는 **UB(터짐)**, unsigned 는 **한 바퀴 돎(조용히 틀림)**. 정수 나눗셈은 소수점을 **버린다**.
ana: 🚗 int = 계기판 끝을 넘으면 차가 고장(UB). unsigned = 주행 거리계처럼 999999 다음 000000 으로 돌아감.
h: 기본 타입 한눈에
tbl: 종류 | 타입 | 보통 크기
r: 정수 | `short` `int` `long` `long long` | 2 / 4 / 4~8 / 8 바이트
r: 실수 | `float` `double` | 4 / 8 바이트
r: 참/거짓 | `bool` | 1 바이트
r: 문자 | `char` | 1 바이트
r: 없음 | `void` | —
star: 표준은 크기를 **보장하지 않음**. 보장하는 건 순서뿐: char ≤ short ≤ int ≤ long ≤ long long.
h: 넘치면? signed vs unsigned
tbl:  | int (부호 있음) | unsigned (부호 없음)
r: 범위 넘으면 | ❌ **UB** | 한 바퀴 돎
r: 예 | 21억 + 1 → ??? | `3u - 5` → 4294967294
r: 위험 | 최적화로 이상하게 깨짐 | 조용히 거대한 수
vs: ❌ 이미 넘친 뒤 검사 | ✅ 넘치기 전에 검사
bool willOverflow(int x)
{
    return x + 1 < x;  // 이 자체가 UB
}
--
bool willOverflow(int x)
{
    return x == std::numeric_limits<int>::max();
}
:end
h: 정수 나눗셈
tbl: 식 | 결과
r: `7 / 2` | **3** (소수점 버림)
r: `7.0 / 2` | 3.5
r: `static_cast<double>(a) / b` | 실수 나눗셈
trap: `unsigned size {5}; i < size - 6` > 부호 있는 int 사용 > 0 - 1 이 42억이 되어 거의 무한 반복
trap: `sum / count` 로 평균 (둘 다 int) > `static_cast<double>(sum) / count` > 소수점이 사라짐
mem: signed 는 **터진다**(UB), unsigned 는 **돈다**(wrap)
key: 정수는 int, 크기는 보장 X
key: int 오버플로 = UB, unsigned = 한 바퀴
key: `7 / 2 == 3`

# p1-11 | 실수 · bool · char | Ch 4.7~4.12
sum: 실수는 **근삿값**이라 `==` 비교 금지. bool 은 **1/0** 으로 찍힌다. char 는 사실 **작은 정수**(`'A'` = 65).
ana: 📏 실수 = 눈금이 유한한 자. 0.1 을 정확히 잴 눈금이 없어서 0.1000000001 처럼 근처 값으로 잼.
h: 실수
code:
std::cout << (0.1 + 0.2 == 0.3);   // 0 (false!)
// 0.1 + 0.2 = 0.30000000000000004
:end
tbl: 알아 둘 것 | 내용
r: 왜 틀려? | 0.1 은 2진수로 딱 떨어지지 않음 (1/3 = 0.333… 처럼)
r: 정밀도 | float ≈ 7자리, double ≈ 16자리
r: 기본 | **double** 을 쓴다
r: `3.2e5` | 3.2 × 10⁵ = 320000
h: bool
tbl: 코드 | 출력
r: `std::cout << true;` | **1**
r: `std::cout << std::boolalpha << true;` | true
r: `if (0)` | 거짓 (0 만 false, 나머지는 true)
h: char 와 static_cast
tbl: 코드 | 결과
r: `char ch { 'A' };  cout << ch;` | A
r: `static_cast<int>('A')` | **65** (문자 코드)
r: `'A' + 1` | **66** (B 가 아님! int 로 바뀜)
r: `char c { 65 };  cout << c;` | A
li: 변환은 `static_cast<타입>(값)` — C 스타일 `(int)x` 는 쓰지 않기
star: `'A' + 1` 은 **66**. 실수는 **==로 비교하지 않는다**.
trap: `if (0.1 + 0.2 == 0.3)` > 오차 범위로 비교 (2회차) > 근삿값이라 거의 항상 false
trap: `if (x = 5)` > `if (x == 5)` > `=` 는 대입이라 항상 참
trap: `std::cin >> ch;` 로 여러 글자 입력 > 한 글자씩 읽힌다는 걸 기억 > 남은 글자가 다음 입력으로 딸려 감
mem: char = **변장한 정수**. 출력할 때만 글자 옷을 입음
key: 실수는 근삿값 → `==` 금지, 기본은 double
key: bool 은 1/0 출력 (`boolalpha` 로 true/false)
key: `'A'` = 65, `'A' + 1` = 66
